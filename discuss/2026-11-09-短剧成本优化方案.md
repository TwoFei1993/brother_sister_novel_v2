# 短剧成本优化方案（对照小云雀短剧 Agent 3.0 拆解产出）

> 2026-11-09 / 目标：**生图花费最小化**。对照小云雀「片段重拍」「智能预演」「全局角色管理」等能力，
> 评估 v3 短剧流程（Phase 0-4，见 [2026-11-07-短剧生成功能设计共识.md](./2026-11-07-短剧生成功能设计共识.md)）的性价比改进项。

## 一、评估结论

| 项 | 判定 | 理由 |
| --- | --- | --- |
| A. 四宫格分帧化 + 单帧重roll | ✅ 做 | 核心省钱项，见下方账 |
| B. 站位快览（轻量） | ✅ 做 | 纯前端零 API 成本，生图前拦站位废图 |
| C. 成本仪表盘（spendLog 记账） | ✅ 做 | 重roll 浪费可见化，反哺 prompt 模板迭代 |
| D. 角色妆造变体系统 | ❌ 不做 | 设定图版式已含多套服装+三视图（characterSheetPrompt），prompt 文字可指定服装；完整变体系统属过度设计 |
| E. TTS 对白直出 | ❌ 不做 | 新增 API 花费，与成本最小目标直接冲突；音频继续走即梦/剪映手动（零 API 成本） |
| F. 3D 导演台 / 视频API直出 / 重制转绘 | ❌ 不做 | 重实现或高单价，与「不烧钱」硬约束冲突 |

## 二、A 项的成本账（挑战 D7，本方案替代之）

D7 整图模式下「修镜头 = 整张重roll」的隐藏成本是**四格联合满意陷阱**：
单格满意率 p 时，整张一次过的概率只有 p⁴（p=0.5 → 6.25%），期望要重roll 约 1/p⁴ 张才能整张满意。

| 模式 | 首打（一镜头） | 修一格 | 全满意期望张数（p=0.5） |
| --- | --- | --- | --- |
| D7 整图（现状） | 1 张 | 整张重roll，4 格全部重新抽卡 | ≈ 16 张 |
| 分帧（本方案） | 最多 4 张 | 只重roll 该帧，其余保留 | ≈ 8 张 |

且现实中「3/4 格能用就行」的心态下差距更大：整图模式仍要整张重roll（4 张钱的风险），
分帧只补缺的那 1 张。**同样满意标准下总花费约省一半，单次修补确定性 1 张钱。**

### 实现要点

- 数据：`shot.gridParts[]`（四格画面描述数据化，AI 拆镜头时写入，可编辑）、
  `shot.frames[]`（`{index:1-4, image, rolls}`，rolls 为该帧累计重roll 次数）；`gridImage` 保留兼容旧数据。
- 生图：`POST /duanju/images` 新增 `kind:'frame'` + `frameIndex`；单帧 prompt = `buildFramePrompt(shot, i, project)`（画风+人物锚点+场景+该格描述），参考图逻辑同 shot。
- 展示：前端 CSS 2×2 排四帧（无需真拼图文件）；「下载拼图」用浏览器 canvas 现拼（导出即梦/存档用）。
- 导出包：有帧导出 `E1-S01-F1..F4.png`，旧镜头仍导整图。
- 兼容：旧 `gridImage` 镜头正常显示；旧缓存页面 PATCH 全量 shots 会覆盖新字段（既有全量替换语义的已知风险，server+client 同镜像部署，接受）。

## 三、C 项记账设计

- `project.spendLog[]`：每次生图 server 持锁追加 `{ts, kind, refId, note?}`（frame 带 `frame-N`），cap 保留最近 5000 条；客户端只读（PATCH 白名单不含）。
- 仪表盘（出图/导出 tab 顶部）：记账张数按类型分桶、重roll 张数（同 key 重复计数）、现存产物盘面数、按 0.2 元/张估算花费。
- 升级前的存量图无日志，盘面数单独展示。

## 四、B 项站位快览

`parseStaging(staging, charNames)`：按「左/中/右」关键词就近归位角色名，三区 chips 展示在镜头卡站位输入框下——纯函数 + 纯展示，零依赖零 API。
