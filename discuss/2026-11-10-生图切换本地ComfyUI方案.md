# 生图切换本地 ComfyUI（Z-Image-Turbo）实施方案

> 2026-11-10 / 用户决策：短剧域生图全部接入本地 ComfyUI（零 API 成本），云端 provider 保留为降级选项。
> **✅ 2026-11-11 已实施完成并通过端到端实测**（见文末「七、实施与验证记录」）。

## 一、已验证的技术底座（2026-11-10 实测）

- 本地 ComfyUI v0.44.0（D:\ComfyUI）+ Z-Image-Turbo int8 全套（11.3GB），中文提示词直出，秒级出图
- 设定图版式定稿：**横版 1344×768**，左一张头部大特写 + 右侧正面/侧面/背面全身三视图（与用户样图布局一致，见 output/z-image-turbo/sheet-v4_00001_.png）
  - 注意：竖版画幅会触发模型的 2×2 重复铺排先验，设定图必须用横版
- 分帧图：9:16 竖屏 768×1344 实测通过
- 场景图：16:9 横版（1344×768 同款）
- API workflow 底稿：D:\ComfyUISetup\templates\z_image_turbo_api.json（占位符化后内置进 App）

## 二、架构决策

1. **浏览器直连**（与视频通道一致）：client → ComfyUI（http://127.0.0.1:8188），产物 blob 回流 server 归档。
   理由：server 可能 docker 部署够不到用户局域网；视频通道已验证此架构。
2. **provider 单点分流**：所有生图调用已经 `generateDuanjuImage`（api/duanju.ts:45）收口。在此函数内按 provider 分流：
   - `comfy` → 浏览器直连本地 ComfyUI，生成后走 `uploadDuanjuImageFile` 回流归档
   - `minimax/zhipu/seedream` → 原有 server API 路径不动（降级通道）
3. **ImageQueue 批量队列自动获得本地生图能力**（队列任务调 generateDuanjuImage，无需改队列）。
4. **一致性边界（诚实声明）**：Z-Image-Turbo 纯文生图无参考图输入；分帧角色一致性第一阶段靠提示词外观锚点（与云端 subject_reference 有差距）。第二阶段用 Qwen-Image-Edit-2511（定妆照参考生图，~16GB）补齐，另行决策。

## 三、改造清单

### client 侧
1. `features/duanju/lib/comfy.ts` 重构：抽通用 `submitAndPoll`（提交→轮询→提取→下载），视频/生图共用；新增 `generateImageOnComfy(cfg, {prompt, width, height, seed})`，注入 `<<PROMPT>>`/`<<WIDTH>>`/`<<HEIGHT>>`/`<<SEED>>` 占位符；产物按扩展名分流（png 图 / mp4 视频）
2. `ComfyuiConfig` 扩展 `{url, videoWorkflow, imageWorkflow}`；`loadComfyConfig` 兼容迁移旧结构（旧 workflow 字段 → videoWorkflow）；**imageWorkflow 缺省时用内置默认模板**（Z_IMAGE_TURBO_DEFAULT，含尺寸/seed 占位符）——用户填完地址即可用，零配置出图
3. 新增 `useLocalImageGen` 或在 `generateDuanjuImage` 内分流（按最小改动原则：分流做在 api/duanju.ts 的 `generateDuanjuImage`，返回值对上层透明）
4. `stores/settings.ts` `imageProvider` 联合类型加 `'comfy'`
5. `ImageProviderPanel` PROVIDERS 数组加 comfy 项（免费·本地·秒级标签）；`ComfyUIPanel` 加生图工作流字段（显示内置默认，可覆盖）
6. 修 `ScenesPane.tsx:88` 未传 provider 的漏网之鱼
7. 设定图提示词模板改造：`characterSheetPrompt` 改为 v4 定稿版式（横版描述）；`aspectRatio` 映射：character→横版 1344×768，scene→1344×768，frame→768×1344

### server 侧
8. 回流端点 `POST /works/:id/duanju/images/upload`（images.ts:256）扩展 `kind: 'frame'` 支持（带 shotId/frameIndex/rolls 语义），复用 `attachImage` 既有分支（images.ts:104-115 已有 frame 逻辑）
9. spendLog：comfy 来源标注 0 成本（spendStats 的 YUAN_PER_IMAGE 不适用本地免费图；在 spendLog 记 0 或加 source 标记）

### 占位符约定（内置默认 workflow）
- `<<PROMPT>>` → CLIPTextEncode.text
- `<<WIDTH>>`/`<<HEIGHT>>` → EmptySD3LatentImage
- `<<SEED>>` → KSampler.seed（每次随机——重roll 出新图）

## 四、降级与错误路径

## 六、实施中踩到的坑（重要经验）

1. **ComfyUI 默认拒绝跨域**：对带 Origin 的请求返回 403（aiohttp 默认无 CORS 头）——浏览器直连架构必须加启动参数 `--enable-cors-header *`（已写入 `scripts/comfy-start.sh`）。
2. **多行提示词破坏 JSON**：`characterSheetPrompt` 用 `.join('\n')`，真实换行嵌进 JSON 字符串值后 parse 报「Bad control character」。修复：占位符注入值统一 `JSON.stringify(value).slice(1,-1)` 转义（comfy.ts injectWorkflow），提示词含换行/引号/控制字符均安全。
3. **错误信息要带原始原因**：injectWorkflow 最初吞掉 JSON.parse 的 SyntaxError，排查多走弯路；现已带上原始 message。
4. dev.sh 前台 wait 设计挂在会话后台任务下会被超时杀——用 `nohup … &` 独立进程跑（ComfyUI 同理，PowerShell Start-Process）。
