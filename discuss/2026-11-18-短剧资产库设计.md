# 短剧资产库设计（讨论稿）

日期：2026-11-18
状态：待评审——确认后才动代码

## 1. 背景与问题

短剧模块的资产（角色档案、场景、风格签名）目前锁在每个作品目录里：

```
v3/data/works/<作品uuid>/duanju/project.json
  characters[] = { id, name, profile(文字描述), sheetImages(设定图) }
  scenes[] / visualSignature
```

新作品哪怕用同一批角色，也要从头建档、重新生成设定图（约 6 张图 × 2 分钟）。跨作品复用全靠手工复制 JSON 和图片文件。

小说主业务侧已经有成熟的资产库架构（`server/src/routes/library/`：角色卡/世界书/预设/正则/势力，数据在 `data/characters/*.json` 等），本设计照它的模式给短剧加一套。

## 2. 数据结构

```
v3/data/duanju-assets/
  characters/<assetId>/
    asset.json        # { id, name, profile, visualSignature?, tags[], createdAt, updatedAt, sourceWorkId? }
    images/
      portrait.png    # 左特写 704×1024
      triview.png     # 三视图 1344×1024
  scenes/<assetId>/
    asset.json        # { id, name, description, tags[], ... }
    images/
      scene.png       # 场景图
  styles/<assetId>/
    asset.json        # { id, name, stylePrefix, visualSignature, ... }  # 风格签名（可整段复用）
```

原则：
- **与生图模型解耦**：资产只存文字档案和图片，不绑定 Z-Image / 2511 / H3-Image，换模型不影响复用。
- **与作品数据格式同构**：`asset.json` 的字段名和 `project.json` 里的 `characters[]` 对齐，导入=字段平移，不需要转换器。
- 图片按现状尺寸入库，不做二次处理。

## 3. 后端（照 library 模式）

新文件 `server/src/routes/library/duanjuAssets.ts`（如超 400 行拆子文件）：

| 路由 | 作用 |
|---|---|
| `GET /api/library/duanju-assets/:type` | 列表（type = characters / scenes / styles） |
| `GET .../:type/:id` | 详情 |
| `POST .../:type` | 新建/存入（含图片上传，multipart） |
| `PUT .../:type/:id` | 更新 |
| `DELETE .../:type/:id` | 删除 |
| `POST .../:type/import-from/:workId` | 从作品导入（按角色 id 提取 profile + sheetImages） |
| `POST .../:type/:id/to-work/:workId` | 导入到作品（合入 project.json，同名跳过/改名可选） |

挂载进现有 `libraryRouter`，鉴权沿用 `authRequired`。

## 4. 前端

`client/src/features/duanju/` 下新增 `assets/` 目录（保持每层 ≤8 文件）：

- `AssetLibraryPanel.tsx`：三 tab（角色/场景/风格），卡片列表 + 预览 + 导入到当前作品
- 入口：DuanjuWorkbench 工具栏加"资产库"按钮
- 角色编辑页加"存入资产库"动作（把当前角色的档案+设定图打包入库）
- 新作品创建流程：可选"从资产库导入角色/场景"

## 5. 迁移工具

一次性脚本（scripts/，跑完可删）：扫描 `data/works/*/duanju/project.json`，列出每个作品的角色/场景清单，按选择批量入库。首个候选：仙侠剧（陆惊尘/沈青鸾/魏无痕 + 宗门比剑台场景）。

## 6. 范围外（明确不做）

- 版本管理、更新历史
- 云端同步/多机
- 冲突合并（导入时同名角色默认跳过，手动改名）
- 视频资产（成片/分镜帧不入库）

## 7. 实施顺序

1. asset.json schema + 后端 CRUD + 测试
2. 前端面板 + 入库/导入动作
3. 迁移脚本 + 仙侠剧三角色入库验证
4. 新作品创建流程接入

预计改动：server 2~3 个文件、client 4~5 个文件、scripts 1 个。全部走仓库现有模式（不引入新依赖）。
