> 2026-11-10 / 调查产出。前置调查：H3 已于 2026-08-03 开源 H3-Base 权重（42.5GB/33B），
> ComfyUI day-0 原生支持；许可证排除美/欧/英/韩，中国大陆可用。
> 你的硬件：RTX 5070 Ti Laptop（16GB GDDR7）= 社区验证的「从容档」。

## 一、ComfyUI + H3 安装实测清单（按步执行，预计半天）

### Step 0：环境预检（10 分钟）
- [ ] NVIDIA 驱动 ≥ 570.xx（50 系 Blackwell，装最新 Game Ready/Studio 均可）
- [ ] 磁盘空间 ≥ 80GB（权重 int8 版约 21GB + 全量 42GB 可选 + ComfyUI 环境 10GB + 输出缓存）
- [ ] （可选）关闭笔记本节能模式：生成时长批任务需满血散热

### Step 1：安装 ComfyUI（30 分钟）
- [ ] 下载 Windows 便携包（github.com/comfyanonymous/ComfyUI releases 的 `ComfyUI_windows_portable_nvidia.7z`）→ 解压到 `D:\ComfyUI`（勿放中文路径）
- [ ] 首次启动：`run_nvidia_gpu.bat` → 浏览器开 `http://127.0.0.1:8188` 即成功
- [ ] 装 ComfyUI-Manager（Menu → Manager 按钮；缺节点自动装依赖全靠它）

### Step 2：下载 H3 三类组件（40 分钟，视网速）
从 ComfyUI 重打包仓 / HuggingFace（`MiniMaxAI` 官方 org）下载并放入：

| 组件 | 放置目录 | 说明 |
| --- | --- | --- |
| 扩散模型（H3-Base transformer） | `models/diffusion_models/` | 选 **fp8 或 int8 pruned 版**（16GB 显存档；全量 42GB 是 bf16） |
| 文本编码器 | `models/text_encoders/` | H3 配套 T5/词表编码器 |
| VAE ×2 | `models/vae/` | 视频VAE + 音频VAE（H3 带音频生成是特色） |

> 显存/文件选择速查：16GB 显存 → fp8 主模型即可 720p 带音频；12GB（3060 档）→ int8 pruned 480p；
> 8GB → 社区 int8 极速整合包（自动补帧/25 步采样）。

### Step 3：加载 H3 官方模板工作流（15 分钟）
- [ ] ComfyUI 菜单 → Workflow → 模板库搜「MiniMax H3」（day-0 自带）→ 加载
- [ ] 按模板标注把三个模型节点指向 Step 2 的文件
- [ ] 首跑：文生视频 4 秒 480p 试水（验证环境），预期 3-10 分钟出片

### Step 4：实测三场景（1-2 小时，核心验收）
- [ ] **文生视频**：直接提示词出片（基线质量）
- [ ] **图生视频（首帧）**：⭐ 用你 App 导出的分镜帧（美食书 S01-F1 雨夜李薇）作首帧 + 镜头提示词 → 看人物一致性与动作衔接
- [ ] **多参考 r2va**：⭐⭐ 角色 A 设定图 + 角色 B 设定图 + 场景图 + 分镜帧（≤9 张）一次传入 → 验证「多角色镜头一致性」——这是 image-01 做不到、H3 原生支持的
- [ ] 记录每条的：耗时 / 显存峰值 / 质量（人物脸崩不崩、文字、音频）/ 分辨率档

### Step 5：验收标准（决定是否接入 App）
- [ ] 单条 4-8 秒 720p 视频耗时 ≤ 15 分钟（16GB 档预期 3-10 分钟）
- [ ] 首帧分镜图的人物在成片中不换脸
- [ ] 带音频输出可用（省后期配音对口型）

**全部达标 → 回 App 说「接 ComfyUI 通道」**：视频环节从「导出去即梦手动」升级为「App 内一键本地生成，零 API 成本」。

## 二、ComfyUI 本地 API（App 接入的技术底座，已调研）

- 提交任务：`POST http://127.0.0.1:8188/prompt`（body = workflow JSON + client_id）
- 轮询：`GET /history/{prompt_id}` → 完成后 `GET /view?filename=...` 取片
- 我们 App 的接法：第四生图/视频通道「本地 ComfyUI」——server 代理到 `127.0.0.1:8188`，
  分镜帧图转 Data URL 注入 workflow 的 image 节点，产物 mp4 落 `duanju/videos/`（回传逻辑复用）
- 无需密钥（本地服务）；设置页配置 ComfyUI 地址即可

## 三、「导演分镜」学习报告（MiniMax 官方故事板/导演台）

### 它是什么
H3 生态的「故事板模式 / 导演台工作流」= **多参考一致性 + 组图/组视频的一站式生成**：
- 输入：统一的故事描述 + 角色 Set（设定图）+ 场景 Set + 多宫格分镜参考（≤9 张图）
- 输出：风格/角色/场景跨镜头统一的视频序列——官方原话「让不会镜头的你也能成片」
- 社区形态：「导演台 3.0」工作流（多参多宫格 + 音画同步 + 提示词模板 + 手册）、「H3 导演台全能工作流」（文生/图生/首尾帧/参考生视频一个工作流全包）

### 技术底座（API 已实证的规格）
- H3 r2va：`text` + 参考图 **≤9 张**（role=reference_image）+ 参考视频 ≤3 + 参考音频 ≤3
- prompt 上限 7000 字符（API 版）；请求体 ≤64MB
- 与首尾帧模式互斥（一次请求二选一）

### 对我们 App 的借鉴（三步演进，已映射到现有结构）
1. **多角色一致性升级（价值最大）**：现痛点=「分帧只带首个出场角色参考图（image-01 多参考不稳）」。
   H3 r2va 参考图 ≤9 张 → 一个镜头的**全部出场角色设定图 + 场景图 + 帧构图**一次传入。
   数据结构已就绪（shot.characterIds[] + 主参考图），只差 provider 支持。
2. **gridParts → 故事板组图**：我们的 `gridParts[F1-F4]` 与 H3 组图模式（sequential_image_generation）
   输入结构同构——分帧描述可直出「故事板参考」。
3. **视频通道第四极**：本地 ComfyUI H3（免费）/ H3 API 按量（等额度）/ 即梦手动（现状）——
   三路视频生成按成本质量自选。

### 与现有分镜系统的差异（诚实对照）
- 我们的 AI 拆镜头（LLM 出景别/运镜/动作/台词/声音/四格描述）≈ 剧创「导演分镜」的**结构化分镜脚本**层
  ——这部分我们已自建且可编辑可导出；
- H3 故事板/导演台补的是**执行层**（多参考出片 + 音画同步）——两者是上下游关系，不是替代关系。
- 即：App 出「导演分镜脚本+资产」→ H3/ComfyUI/即梦 出「成片」。
