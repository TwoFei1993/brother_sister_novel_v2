# 安卓 App 设计共识（grill-me 评审产出）

> 2026-10-22 / 基于 v3（酒馆化改版）代码库现状逐题拷问后的共识记录。
> 状态：**Phase 1/2/3 全部实施完成（2026-10-23）**，931 测试全绿；见文末「实施进度」与 `v3/docs/Phase2-3深度测试报告.md`。实现细节以本文档为唯一起点。

## 一、现状盘点（代码库探查结论）

| 现状事实 | 对 app 方案的影响 |
| --- | --- |
| v3 = client(React 19 SPA，提示词引擎纯函数) + server(Express 薄代理) + shared(zod) | 创作引擎可整体复用 |
| **无独立"章节"实体**：一章 = 消息流里一条 assistant 消息（`MessageChapter` 仅 index+title） | 章节版本体系必须新建在消息模型上 |
| **已有 swipe 机制**：`Message.swipes: string[]` + `swipeId`（上限 20），chat 重roll=追加候选 | "章节多版本"的天然地基，升级而非重造 |
| library（characters/worldbooks/presets/regex）是全局池，无归属概念 | 素材归属模型为纯新增 |
| planner feature 已有聊天式创作向导（严格 JSON 协议：reply/questions/outline → importAllAssets → createWork） | "对话大纲"约 80% 雏形已存在，做扩展 |
| 鉴权=单密码 + HMAC token HttpOnly cookie，7 天；存储=JSON/JSONL 文件 | 单用户 MVP 鉴权原样沿用 |
| workbench 是桌面多面板布局（react-resizable-panels） | 手机需全新移动布局 |

## 二、已确认的决策（逐题结论）

### D1 用户模型：先单用户，多用户 Phase 3
- MVP = 作者自己的创作+阅读工具，单密码登录沿用。
- 阅读模式（单用户期）= 你自己的"读者视角/审稿流"；划线评论 = 审稿笔记。
- 沟通模式：仅占位 tab，留言板等功能 Phase 3 与多用户一起做。

### D2 技术路线：Capacitor 壳 + v3 代码库
- v3 client 整体装进 WebView 壳出 APK；网页端与 app 共用同一套代码。
- 新功能（上架/版本/阅读/素材绑定）全部用 React 写在 v3 代码库，一次编写双端受益。
- 不用 RN/Flutter/原生（避免与 v3 永久分叉、避免重写提示词引擎）。

### D3 章节版本：扩展 swipes 为结构化版本 + 双指针
- `swipes: string[]` 升级为结构化版本对象：
  `{ id, name, content, origin: 'ai' | '手改', createdAt }`；版本名可改、同书内唯一。
- **双指针**：
  - `swipeId`（现有）= 生成基底/激活版本——写第 N+1 章时上下文取它，可随便切；
  - `publishedVersionId`（新增，可 null=未上架）= 阅读端展示版本，独立于激活指针。
  - 允许"基于 v3 草稿续写，阅读端仍展示 v1"。
- 存量数据一键迁移：旧 swipes 自动命名 v1/v2/…；"生成新版本并手改"= 复制当前版本追加，命名追加"手改N"后缀。

### D4 素材库：纯复制不共享 + 归属可选三态
- 跨书复用一律深拷贝出新实体挂到目标书，两本书独立演进，无共享引用。
- 归属为**可选**字段：`origin: { type:'book', bookId } | { type:'external', note } | { type:'none' }`。
  新素材不强制挂书；老素材迁移时统一标 `external/none`，要用时走复制流程。
- 绑定三态（关联生效时机）：初始绑定（全书生效）/ 第 N 章及之后绑定 / 待绑定（AI 检出待确认）。
- 书改名跟随 = 按 bookId 引用、展示时解析书名，天然跟随。
- 世界书/角色卡/势力介绍三类同模型；势力介绍为新增素材类型。

### D5 对话大纲：扩展 planner + 关键词按钮双通道 + 同会话两阶段
- 在现有 planner（聊天式向导）上扩展，不重做；补齐：势力介绍提取、冲突检测提示、迭代阶段。
- **关键词+按钮双通道**：三句魔法关键词（建素材库/建书/章节加新版本）保留前端规范化字符串匹配（去空格比对，不用 LLM 判断高危动作）；AI 每次提示关键词时气泡内直接渲染【确认】按钮，点击=以作者身份自动发送该关键词，同一代码路径。
- **同一会话，创建→迭代两阶段**：建书完成后会话自动切为本书迭代阶段（章节重写对话、新版本生成、素材补充），历史延续，上下文不断。

### D6 创作中布局：底部 tab 切换四分区
- 正文全屏为主视图，底部 tab：正文 / 大纲对话 / 版本 / 资料。
- 辅助资料页内分区列表（大纲高亮本章节点、章节细纲、出场角色卡、世界书、势力介绍、本章作用与钩子），点开展开。
- 不照搬桌面多面板。

### D7 划线评论：文本快照锚 + 失效降级
- 评论结构：`{ 章节, 版本id, 段落序号, 引用文本±上下文, 类型: 改错/添加/感悟… }`。
- 定位：先按版本+段落，找不到再全文搜引用文本，两步皆败→标记"原文已变"，可手动重新锚定，评论永不丢。
- 评论属**版本资产**：换版本后旧版本评论折叠为"历史批注"仍可查；按类型总结时标注章节+版本+原句。

### D8 待绑定检测：生成时 side-channel 顺带输出
- 章节生成提示词要求模型在正文之外顺带输出结构化"本章新角色/新势力/新世界观"清单
  （沿用 rawThinking/activatedEntries 的 side-channel 惯例）。零额外 LLM 调用，写完自动弹待绑定提示。

## 三、"不影响现在的网站"的实现保证（D2 与该约束的调和）

1. **UI 层零侵入**：app 四 tab 信息架构做成独立移动端路由树（如 `/m/*`），现有桌面路由/页面/组件路径一律不动。上架管理、阅读模式、移动创作布局均为新组件挂新路由。
2. **数据层必须动，但向后兼容**：swipes 结构化迁移不可避免（版本体系的地基），由 zod schema 升级 + 自动迁移脚本 + 迁移前 `bash scripts/backup.sh` 兜底；现有桌面 UI 适配新结构后行为不变。
3. **测试保护**：v3 已有全 workspace vitest；迁移与改动以"现有测试全绿 + 新增测试"为验收线，跑分见 `bash scripts/test.sh`。
4. 桌面网站后续（可选、非义务）再接入阅读模式等功能；不接也不影响 app。

## 四、三阶段计划

- **Phase 1 地基闭环**：swipes 结构化 + 双指针迁移 → 上架开关+草稿态保存流（进编辑模式→本地暂存→总开关保存才生效）→ 阅读模式（上架书阅读+划线评论）→ 四 tab 框架 → Capacitor 打包出首个 APK。
- **Phase 2 素材与对话**：素材归属/复制/绑定三态/待绑定检测（D4/D8）、对话大纲迭代阶段（D5 后半）、阅读书架分类排序。
- **Phase 3 多用户与沟通**：多账号体系（后端从单密码升级）、沟通模式（留言板/系统建议/想看的书）、评论体系面向真实读者。
