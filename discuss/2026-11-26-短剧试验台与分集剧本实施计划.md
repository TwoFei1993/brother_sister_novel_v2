**走查抓到并已修的问题**

1. 续接时把整份检查点当归档参数发给服务端，多出的字段被严格校验拒绝（页面上是「试验记录元数据不合法」）。单测只抽查了其中两个字段，没照到；已改成精确断言。
2. 扩写结果在本地留断点，任务在页面离开期间失败时，下次恢复可能取到上一次的旧提示词。改成结果一到手就取走断点。
3. 云端出图请求体多带 `seed` 字段，会被服务端拒绝。
4. **范围外的既有缺陷**：短剧资产库前端请求多了 `/library` 一层，服务端没有这一层，真实环境里三类资产从 11-18 上线起就 404。已修并加契约测试。
5. **会让 CI 构建失败**：试验台的检查点文件在前端包里直接 `import { z } from 'zod'`，而前端包没有声明 zod。主工作区里类型检查能过（残留的提升依赖），干净安装后找不到模块。已把校验规则搬到 `shared/duanju/lab.ts`（只有服务端和共享层依赖 zod），前端只 import 共享层导出的规则。

**推送前的「隔离检出」验证（工作区混着别人未提交的改动时必须做）**

主工作区的类型检查和测试通过，不代表推上去的内容自洽——它里面还有别人的在途改动和残留依赖。做法：

1. `git add -- <自己的明确路径>`，`git status` 确认暂存区只有自己的、未跟踪项里只剩别人的。
2. `git write-tree` → `git commit-tree <树> -p HEAD -m "verify only"` 造一个**不在任何分支上**的临时提交。
3. `git worktree add --detach ../_verify <临时提交>`，在其 `v3/` 下 `pnpm install --frozen-lockfile`（13 秒，全部命中缓存）。
4. 在里面跑 `typecheck.sh`、`build.sh`、`test-pkg.sh client|server|shared`。改了代码就重新暂存、重新造临时提交，`git -C ../_verify_duanju checkout --detach <新提交>` 更新检出后重跑。
5. 已知的无关失败：共享层 `types.test.ts`、服务端 `card-png` / `tavern-io*` 读的本地样本文件没入库。`test.sh` 会在共享层失败后停下，所以要分包跑。

**真实模型全流程（走查专用作品，3 章短文，共 9 次调用、约 17 分钟）**

- 拆解：3 集，厚梗概 79 / 94 / 123 字，每集带原文首句与末句，逐字正确。
- 角色、场景只补缺失：事先放进去的「老陈」「深巷面馆」没被动。
- 分集剧本：1153 / 847 / 1162 字，场次式。第 1 集对照原文核对：情节全覆盖、原台词保留、结尾停在切片末句、没有越界到第 2 章。
- 拆镜头：第 1 集 12 个、第 2 集 10 个、第 3 集 5 个，各归各集。跑完后进度条消失、断点清空、无失败项。

**实测暴露、待裁定的设计缺口**

- 流水线提取的场景档案读的是全文，把故事结尾的道具状态写了进去（「泛黄火车票…辣椒罐压纸条…后门灯灭」）；拆镜头把档案当【视觉基调】拼进每一集的镜头画面提示词，于是第 1 集 12 个镜头的画面提示词全都带着第 3 集结尾的道具。镜头本身的动作与台词没有串集。建议：场景提取只写不随剧情变的结构，道具以本集剧本为准。没有擅自改既有的提取规则。

**对照官方提示词技能**（评审期间环境里装上了 MiniMax 官方的 `h3-image-prompt-writing`）：

- 带参考图的写法按官方指南重写：三段式；每个主体单独一句关系（`<Subject N> is fully preserved.`）；每张参考图交代用途；取景由底图决定。
- 文生图规则补了三条：先布局后细节；身体要站得住（朝向、可见的体表、手、支撑点、接触关系对得上）；不要为了迁就姿势镜像左右布局。
- 修正一处：之前把否定句一律禁掉，写得过死。官方明确建议在没有文字要求时写一句「图中没有任何文字、字母或数字」，与你 11-24 的结论一致（低关联瑕疵可以用否定）。
- 这些规则文本没有实测。官方建议提示词用英文写；试验台默认中文，语言开关在输入区。
