## 1. 背景

- **测试生图**：现在所有生图都必须挂在角色、场景或镜头上，没有独立入口；底层通道、画风层、归档都能复用。
- **分集剧本**：系统里没有「每集的剧本正文」。小说转短剧时全文直接当剧本，拆镜头时每集都读「全文 + 50 字梗概」，由模型即兴转成镜头；AI 生成只写第 1 集，没有后续集入口。本地 7 个有镜头的短剧作品里，6 个的镜头只在第 1 集，另 1 个第 2 集只有 1 个镜头。

## 2. 功能一：测试生图（试验台）

### 2.1 目标与入口

输入一句简短提示词 → AI 扩写成完整提示词 → 你审批（可改）→ 出图 → 结果可对比、可追溯。

入口放在短剧工作台新增的「试验」tab。理由：复用作品上下文（画风、视觉签名、角色/场景档案、归档目录）；桌面、手机、app 一套代码；不受「剧本定稿」锁。全局独立页（归档无归属）和设置页内按钮（放不下审批流程）不采用。

### 2.2 流程

1. **输入**
   - 简短提示词（必填，300 字内）
   - 画面类型：自由 / 人物定妆 / 场景概念 / 单帧分镜（决定扩写模板）
   - 画幅：9:16（默认）、16:9、1:1、4:5（云端通道没有 4:5，自动隐藏）
   - 输出语言：中文 / English
   - 通道：默认跟随设置页的生图通道，试验台内可临时切换，不影响正式出图设置
2. **扩写与审批**：点「生成完整提示词」→ 走服务端后台 LLM 任务（切出安全）→ 提示词进可编辑文本框。按钮：「重新扩写」「确认出图」。超过该通道的长度上限时禁止出图并提示删减，**不截断**——保证审批的就是送去生成的。
3. **出图**：确认后提交，显示已用时长；完成后出结果卡：图、完整提示词（可复制）、通道、尺寸、耗时。操作：下载、再出一张（本地通道换 seed，云端直接重生成）、用同参数回填微调。
4. **历史**：按时间倒序，可逐条删除。

### 2.3 通道支持矩阵

| | 本地 H3-Image | Seedream | GLM-Image |
| --- | --- | --- | --- |
| 画幅 | 9:16、16:9、1:1、4:5 | 9:16、16:9、1:1 | 同左 |
| seed | 可指定、可复现 | 不可指定 | 不可指定 |
| 提示词上限 | 自设 3000 字 | 2000 字 | 1000 字 |
| 参考图（M2） | 0–3 张 | 1 张 | 不支持 |
| 耗时 | 每张约 2–8 分钟 | 未实测 | 约 20 秒 |
| 费用 | 免费 | 0.12 元/张 | 设置页写的是 0.1 元/张，未核实 |

### 2.4 扩写规则

- **本地 H3-Image**：你 11-24 实验定稿的硬规则直接写进扩写系统词（底图决定一切、无负向词、一帧一瞬间、动作按动力链与几何写、表情用肌肉动作写、主体道具带先行词、已有的手和道具写成保留项）。MiniMax 官方 `h3-image-prompt-writing` skill 本机没装，实施时尝试联网读取作为补充，读不到不影响。
- **云端**：通用中文生图提示词，结尾拼「避免出现：…」，并按通道限长。
- **画风与场景规则**：复用 `prompts-image.ts` 的画风层和 `prompts-scene.ts` 的场景规则。
- 扩写用你设置的主 LLM 通道，关闭思考。

### 2.5 数据与接口

- 记录存 `data/works/<id>/duanju/lab.json`，图片落 `duanju/images/`，与 `project.json` 分离（不参与乐观锁，不撑大它）。
- 记录字段：简短提示词、实际送生成的完整提示词、通道、画幅、宽高、seed、参考图路径、带入的角色/场景 id、产物、耗时。全部用 zod 定义成强类型。
- 接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/works/:id/duanju/lab` | 历史列表 |
| POST | `/api/works/:id/duanju/lab/generate` | 云端通道生成并归档 |
| POST | `/api/works/:id/duanju/lab/images` | 本地通道产物回流归档（multipart） |
| DELETE | `/api/works/:id/duanju/lab/:recordId` | 删除记录及其图片 |

- 写入规则：上游生成不持锁（含重试与下载最长约 7 分钟）；追加和删除是读-改-写，走该作品的写锁（与 `project.json` 共用一把），不会互相覆盖。写记录失败时回滚已落的图片。
- 不复用现有的 `images/upload`：那条路由会让作品版本号加一并写成本记录，试验图不要这些副作用。图片的访问复用现有文件流路由。
- 生成失败不落记录。鉴权沿用 `worksRouter`。

## 3. 功能二：分集剧本（改编 / 续写 / 重写）

### 3.1 数据结构（均为可选字段，旧数据不改也能读）

- 集（`DuanjuEpisode`）新增：
  - `script`：本集剧本正文
  - `scriptSource`：`adapted` 从原文改编 / `continued` 按梗概续写 / `manual` 手写、采用或原文
  - `scriptUpdatedAt`：正文更新时刻
  - `sourceStart` / `sourceEnd`：本集对应原文的首句和末句（各 20 字内），改编时用来切片
- 剧本（`DuanjuScript`）新增 `scope`：`full` 整本小说 / `episode1` 只有第 1 集。小说一键转换时服务端直接写 `full`。
- 镜头快照（`BuiltFrom`）新增 `episodeScriptAt`，用于判定待刷新。
- 项目新增 `pipeline.pauseAfterScripts`（D1 的开关）。
- 在 shared 里定义 `BuiltFromHint` 类型，替换客户端和服务端里重复四处的内联写法（现在是 `unknown`）。

### 3.2 拆解的三处小改

- 每集梗概从 50 字加厚到 150 字内，按「进入状态 → 本集目标 → 转折 → 结果 → 结尾钩子」写。续写没有原文可依，全靠梗概。
- 每集多输出 `sourceStart` / `sourceEnd`。
- 重新拆解合并集列表时：有镜头**或有剧本**的旧集都保留（现在只保留有镜头的）；已有集同时更新锚点。

### 3.3 三种生成模式

| 模式 | 触发条件 | 输入 | 纪律 |
| --- | --- | --- | --- |
| 改编 | `scope=full` 的各集 | 本集原文切片 + 上一集结尾 300 字 + 人物/场景清单 + 下一集梗概 | 忠实原文：不新增设定、人物、关键事件；心理描写转可见动作；原文已是剧本时以保留为主 |
| 续写 | `scope=episode1` 的第 2 集起 | 审核卡 + 人物/场景清单 + 最近两集剧本全文 + 更早各集结尾 300 字 + 本集与下一集梗概 | 按梗概创作，不越界到下一集 |
| 重写 | 用户在已有剧本上填修改意见 | 现有剧本 + 意见 | 只改意见涉及的部分 |

- `scope=episode1` 时第 1 集不调 AI，也不写剧本字段，拆镜头和续写直接读原文。改原文后仍按现在的规则提醒待刷新。状态显示「原文即第 1 集」。
- `scope` 自动推断：原文行首出现 2 次及以上「第 N 章 / 回 / 节 / 卷」标题（N 可以是阿拉伯或中文数字），或超过 1.5 万字 → `full`；否则 → `episode1`。「第 2 集」不算章节标题。粘贴的多集行式剧本会被判成 `episode1`，下拉旁提示可以手改。
- 来源标记：AI 改编 / 续写落库记 `adapted` / `continued`；用户在编辑器里点「保存并采用」记 `manual`；重写不改来源。写入分集剧本时保留集的其余字段（叙事机制、锚点）。
- 空白内容不算有剧本：保存空白等于清除本集剧本。
- 三种模式的输出预算与拆解一致（32000）；输出清洗统一为剥代码块围栏、剥首尾解释行。
- 人物名以角色档案为准（拆镜头按名字精确匹配角色，名字对不上就没有参考图）。

**原文切片定位**（纯函数，两遍）：

第一遍，逐集找「首句 + 末句」：

- 从上一个命中的末句整句之后开始找本集首句：精确匹配 → 前 12 字 → 前 8 字 → 前 5 字。首集从文首找起。
- 再跳过首句整句之后找本集末句，同样的降级顺序。
- 首句、末句都找到才算本集定位成功。范围超过全文平均集长的 4 倍的，按未定位处理（防止降级匹配串到很靠后的位置）。

第二遍，定界：

- 定位成功的集：范围是它的首句到末句。
- 未定位的集：左界是前一个定位成功的集的末句（没有则文首），右界是后一个定位成功的集的首句（没有则文末）。相邻几集都没定位时，它们共用中间这一段。
- 一个集都没定位：全部回退全文。
- 未定位的集，改编提示词里限定「只写本集梗概对应的情节，不写到其他集」，结束时汇总提示「第 N 集按邻集位置估算」或「未找到原文位置」。

### 3.4 剧本 tab

审核卡之后新增「分集剧本」区，每集一张卡：

- 显示：集号、标题、梗概、状态（未写 / 原文即第 1 集 / 已采用·来源）、字数。
- 展开：剧本编辑器 + 操作。
  - 「AI 改编本集」或「AI 续写本集」（按原文性质二选一）
  - 「按要求重写」：展开意见输入框
  - 手动触发的 AI 结果先进编辑器作为草稿，点「保存并采用」才落库；流水线自动写的集直接落库，可随时改
- 顶部：「一键改编全部未写集」、原文性质下拉（D3）、D1 的停靠开关。
  - 「一键改编全部未写集」只写剧本，写完即停；范围不含「原文即第 1 集」那集，确认框写明将调用 AI 几次。
- 编辑器草稿存在模块级，按作品和集隔离，不随组件重挂丢失。
- 老作品没有锚点（3.2 才开始输出）：要先「重新 AI 拆解」才能切片改编，界面会提示。流水线不会覆盖已有的剧本和镜头（见 3.6）。

### 3.5 拆镜头与待刷新

- 拆镜头优先读本集 `script`，没有才回退「全文 + 梗概」。改动在调用方，不动 `prompts-storyboard.ts`（它有未提交的在途改动）。
- 出图时的快照记下 `episodeScriptAt`：本集有剧本记它的更新时刻，没有记 0。
- 待刷新判定：
  1. 快照不为 0：剧本这一项只比本集时刻，不等即待刷新，不再比整本剧本的时间；角色、场景照旧比对。
  2. 快照为 0：本集现在有剧本 → 待刷新；否则与现在完全一样（整本剧本时间 + 角色 + 场景）。
  3. 旧快照没有这个字段：同第 2 条。
- 只标记不自动重生成。内容没改的保存不更新时刻。

### 3.6 流水线

**运行态**：放在模块级（独立的 zustand store），按作品隔离，不放组件 state。启动前先抢占该作品的运行标志，已在运行则拒绝。进度条和停止按钮挂在工作台顶栏下方，切到别的 tab 也能看到和停止。

**启动入口**：

| 入口 | 跑哪些阶段 |
| --- | --- |
| 一键转短剧后的自动拆解完成 | 角色 → 场景 → 分集剧本 → 拆镜头（受 D1 开关影响） |
| 手动「AI 拆解」完成 | 同上 |
| 剧本 tab「一键改编全部未写集」 | 只跑分集剧本，写完即停 |
| 停靠后的「继续拆镜头」 | 从拆镜头阶段接着跑 |

**步骤规则**：

- 角色和场景放在分集剧本前面，是为了写剧本和拆镜头时名字一致。
- 每一步开始前重新读取最新作品数据，不再用启动时的快照。现有的写法把提取之前的空角色清单传给了拆镜头，新写法顺带修掉。
- 拆解结果先等保存成功，再启动流水线；保存往返期间原文暂存在浏览器里，防止页面被回收丢结果。
- 单集容错：某一集写失败不中断，记入失败清单，结束时汇总「第 X 集失败，可重试」。
- 没有分集剧本的集，流水线不拆镜头（现状是即兴拆）。

**已有内容不覆盖**（D8；每一步和断点续跑共用）：

- 角色 / 场景档案：已有非空档案的不动，只补缺失的。想刷新用卡片上现成的「重写」按钮。
- 分集剧本：本集已有剧本的跳过。
- 拆镜头：本集已有镜头的跳过。想重拆去分镜 tab 手动点，那里有确认框。

**停止与被动中断**：

- 点「停止」：当前这一步跑完后停下，删除断点，之后不会自动续跑。
- 页面被回收或刷新：属于被动中断，断点留在浏览器里；下次打开该作品自动接着跑，并提示。
- 同一页面内的重挂（D7 修复前、React 双挂载、切回前台）不会重复启动：模块级运行标志挡住。

**断点**：存 localStorage，记录 `{ 步骤, 集序号, 在途任务 id, 失败集清单, 是否停靠 }`。

- 续跑时先查在途任务：已完成直接取结果，运行中接着轮询，失败或丢失才重提。页面回收后服务端任务照跑完，结果不浪费。
- 超时按实际轮询次数算，不按墙上时钟。否则手机切后台回来会把还在跑的任务误判为超时。

**停靠**（D1 开关打开时）：剧本阶段跑完后停下，断点保留并标「已停靠」，不自动续跑；显示「继续拆镜头」按钮，点击后从拆镜头阶段接着跑，仍有断点保护。

**与手动操作并发**：

- 流水线每次写库成功后，把最新作品数据同步进界面。store 的三个写入点（加载、保存、流水线同步）统一走一个接收方法：版本号不小于当前才接受。这样你在任何 tab 保存不会撞「版本冲突」，晚到的旧响应也不会把版本号退回去。流水线写入撞冲突时重读重试，最多 3 次。
- 流水线运行期间禁用会互相替换的操作：「AI 拆解」「AI 生成剧本」「AI 拆镜头」「一键改编全部未写集」「单集 AI 改编 / 续写 / 重写」。编辑、保存、出图、导出不受限。

### 3.7 刷新不卸载分区（D7）

- 分区的渲染条件改为「作品数据存在」，与加载中、加载失败标记无关。「加载中」只在作品数据为空时显示。
- 首次加载失败（数据为空）显示错误页；刷新失败（数据存在）保留分区，顶部提示「刷新失败，显示的可能是旧数据」。
- 原文和审核卡的本地编辑态：记下「上次同步到界面的值」，本地值等于它才算没有未保存修改。没有未保存修改且服务端值变了才覆盖；有未保存修改时不覆盖，保存以本地为准。保存成功后更新这个基准值。
- 顺带收益：批量出图每张完成都会刷新，现在面板会随分区卸载而消失、旧队列在后台失控；修后面板和队列都保留。

## 6. 明确不做

- 试验台不做视频生成，不做「把试验图存为角色/场景定妆」。
- 不把流水线搬到服务端。浏览器端断点续跑够用；服务端编排是另一个量级。
- 不做「多集整稿自动按集切分」，按整本处理，靠改编规则保留已有台词。
- 不做分集剧本审批门：自动采用、可改，改后镜头标待刷新。
- 不迁移老作品：先重新拆解，再点「一键改编全部未写集」即可补齐。
- 重新拆解不自动清空已有分集剧本（梗概变了也不会动它）。

### 7.5 现存缺陷

- (a) 流水线拆镜头用的是提取角色/场景**之前**的清单（`duanju-pipeline.ts:77,152,157`）。一键转短剧的新作品清单为空，按名匹配会全部落空。未实测后果；3.6「每步取最新」顺带修掉。
- (b) 手机切后台回来，轮询会按墙上时钟误判超时（`duanju-pipeline.ts:40`）。`useBgLlmTask.ts` 有同类写法，本次不动，只让新流水线规避。
- (c) 每次刷新作品数据（批量出图每张完成都会触发）都把全部分区卸载重挂（`DuanjuWorkbench.tsx:132`、`store.ts:51`），编辑中的内容丢失。`store.test.ts` 注释写明了「不重挂」的意图，但没改到渲染条件。即 D7。
