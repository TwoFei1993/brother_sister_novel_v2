## 二、飞书课件对照（训练营第一课：zimg 分镜 → H3 首尾帧视频）

### 2.1 已对齐项（无需动）

| 课件要点 | 我方现状 |
| --- | --- |
| 帧数公式 `max(5,round(a*24))+(5-(max(5,round(a*24))%17))%17` | `framesForDuration` 已实现且更严谨 |
| 首尾帧：背面图→正面镜前图，图序即动作方向 | flf2v F1(起势)→F4(落势)，语义一致 |
| 视频/音频两个 VAE 对应 | 内置 workflow 模板已固化 |
| 模板二「参考这个图，生成背面视角的镜头」 | refMode（2511 编辑指令式：保留+改变+机位）覆盖且更系统 |

### 2.2 差距项（改进方向）

**G1（大）：视频提示词结构化不足——我方最大的单点差距。**

课件的视频提示词是「秒级时间轴 + 人物规格交叉验证 + 光影曲线 + 分层声音设计 + 量化运镜 + 色彩分级 + 全局技术参数」的超结构化长文；我方 `buildLocalVideoPrompt` 只有三句：

```
One continuous cinematic vertical shot: {gridParts[0]}; camera {cameraMove}, {staging}.
<d>[Chinese] {dialog}</d>
Audio: {sound}.
```

具体缺陷：
1. **只用了 F1 描述，F4（尾帧）完全没用**——flf2v 模式下尾帧画面就是 F4，prompt 却不描述「到达尾帧状态」，模型对中间过程的路径约束只剩两张图硬拉；
2. F2/F3（中间两帧描述）也没用——四帧数据在手，时间轴分段是现成的；
3. 人物规格（character.profile 锚点）不注入——首尾帧人物已在图中，但中间过程（转身/走位/换姿态）的骨相/发型/服装约束靠 prompt 补充更稳；
4. 运镜词不量化（「推」vs 课件的「tripod lock-off + 末端极缓 dolly-in ≤0.3m」）；
5. 声音只有一行 sound 文本（课件有 BGM/Foley/VO 分层 + ducking，但一期可只借鉴「动作声与动作对齐」思想）。

改进方案（数据全在，纯 prompt 组装升级，零成本）——`buildLocalVideoPrompt` v2 草案：

```
[总起] One continuous cinematic vertical shot, {durationSec}s ({cameraMove量化}): {actionStart} → {actionEnd}.
[Character spec] {出场角色 profile 拼接（交叉验证首尾帧人物：发型/骨相/服装/配饰）}
[Timeline] 四帧分段时间轴（durationSec 按比例分四段，如 8s → 各 2s）：
  0-{t1}s: F1 描述（precisely match the first frame）
  {t1}-{t2}s: F2 描述
  {t2}-{t3}s: F3 描述
  {t3}-{end}s: F4 描述（arrive exactly at the last frame state）
[Dialog] <d>[Chinese] {dialog}</d>
[Audio] Audio: {sound}.
```

- 运镜量化映射表：固定→`tripod lock-off, no camera movement`、推→`slow dolly-in`、拉→`slow dolly-out`、摇→`gentle pan`、移→`tracking shot`、跟→`camera follows the subject`；
- flf2v 模式 F1/F4 已是首尾帧，时间轴首尾段与图片呼应（「复刻首帧→…→到达尾帧」正是课件「从参考图B到参考图A」的路径描述法）；i2v 挑帧模式 F_N 为首帧，同理只强化首段；
- H3 prompt 上限 7000 字符（API 版），本地通道无此约束，但 gridParts 每格 40-80 字 × 4 + 规格段 ≈ 600-900 字符，远在安全区；
- 需要改动的只有 `prompts-storyboard.ts` 的 `buildLocalVideoPrompt`（约 +40 行）与调用处传参（补 project 以取角色 profile），无 schema 变更、无 server 变更。

**G2（中）：「同镜头换机位」的帧修补模式。**
课件模板二本质是「用已满意的图做参考，换机位重出同镜头另一构图」。我方帧重 roll 目前是「同 prompt 重新抽卡」，构图不可控。可在帧卡加「以此帧为参考换机位」按钮（走 2511 refMode，机位指令 = 该帧 shotSize 构图 ± 视角词），用于「人物满意但构图不满意」的场景，省抽卡。

**G3（小）：镜头时长预设档位。**
课件案例均为 7-8s 单镜头。我方 durationSec 4-15s 自由填，但 H3 Flash 本地 73帧(≈3s)/条 4min、8s(197帧)约 11min——时长越长等待越久。可在拆镜头 prompt 中引导动作密集镜头 5-8s、特写反应镜头 4-5s，并在镜头卡显示预计生成耗时。

**G4（小但立即修）：视频 prompt 里的否定式写法。**
H3 对否定不敏感、对词根敏感（社区铁律，「不要 X」会渲染 X）。我方 `buildLocalVideoPrompt` 默认声音行 `'ambient sound matching the scene, no background music'` 正是否定式——含 BGM 词根，有触发背景音乐的风险。应改为正向描述（如 `ambient sound only: wind, footsteps and cloth movement`）。生图模板里的「无文字水印」同理可复查（Z-Image 语境另论，生图工作流可走 negative prompt 通道而不是写进正向正文）。

## 三、AICG3D 插件与提示词指南体系对照

参考资料含两枚配套插件（节点 ID 互不冲突，可同装）：`comfyui-AICG3D`（生成执行：采样/分段/拼接 + 提示词指南库）与 `comfyui-AICG3D-SKILLS`（提示词工程：Skill 管理/LLM 扩写/质检）。两者均未安装到本地 `D:\ComfyUI`（现状 custom_nodes 仅 GGUF/Manager/SeedVR2/hyperflow）。

### 3.1 提示词指南库核心发现（h3_general 协议 + 17 场景方案，51 文件）

**（a）三层架构**：常驻通用层（h3_general 协议骨架）+ 模式参考层（base/ref，按 T2VA/I2VA/FL2VA/L2VA/Ref2VA 五种输入模式）+ 场景附加层（17 个可插拔方案）。运行时组合 =「完整通用 + 当前模式参考 + 至多一个场景方案」。
→ 我方 prompt 是单体模板，应拆成「协议底座 + 模式骨架 + 场景附加」三层。**i2v 与 flf2v 应有各自协议骨架**（I2VA 首行固定对齐指令 `For the target video, at 0.00 seconds…<Picture 1> is fully referenced`；FL2VA 叙事链 =「第一帧→可观察中间变化→差异缩小→最后一帧」）。

**（b）中文表达七原则**（可直接作拆镜头 system prompt 底座）：时序「当前状态→动作发生→环境反应→动作结果」；抽象词（高级/震撼/电影感）必须转可观察细节；禁元话语（"和之前一样"）；一句只承担一个主要变化。

**（c）可量化节拍语法**（AI 拆解与人工 QC 的硬标准）：单镜 ≤15s；每时段一个主要动作+一种主要运镜；运镜 14 类型 × 幅度(small/large) × 速度(slow/fast) 三维表达；`[Shot 1]` 无时间码后续严格递增（MM:SS.mmm）；`detailed_description` 350-500 英文词；对白密集时优先塞完整口播时间线而非凑字数。

**（d）shot-table-spec 六列镜头表**（我方分镜表最直接对标物）：
①镜头号+时长 ②**连续性交接列**（承接上镜结尾的图面/道具/视线/姿态/声音桥/情绪，并为下镜开场铺垫）③参考锚点（固定地标及**屏幕相对位置**如 `door-frame: right third`；每角色屏幕位置/朝向/初始姿态；**已退场角色状态**跟踪 ≥1 镜；光照基线+本镜修改量）④钩子类型（受控词表 8 种：reveal/reversal/callback/suspense/chase/visual-joke/tender/expression-beat）⑤逐秒指令（每秒五要素：动作姿态表情/运镜/空间位置/声音提示/向下一秒交接）⑥音轨对白轨。
自检门：**每 3 个连续镜头至少 1 个 reveal/reversal/callback，首尾镜必带强钩子**；单镜重要角色 ≤3 人。

**（e）打斗八拍合同**（15s 一镜到底）：八拍 1.5/1.5/1.5/1.5/1.5/2/2.5/3s（开场破局→首交锋→反击留缺口→对手招牌→最低点→大招成形→全力对轰→终结技命中第 3 拍缺口）；情绪曲线「一起两落再大起」；状态锁定双防线（站位后【状态锁定】按时间写死+每拍开头标状态）；逐拍写朝向（正/侧/背对镜头）防莫名正脸；震动配额（轻3+中3+零1+重1+一闪1）；**跨段接力：第一段尾停在大招将成形瞬间不定格，末帧截图作第二段 `<Picture 1>`，两段各自带全套声明（模型无跨段记忆）**。

**（f）对白切点四规则**（zh_dialogue）：切点优先放在一句话结束 / 情绪完成 / 视线改变 / 关系状态明确变化处；口型同步明写、离屏旁白明写嘴唇闭合；跨镜对白 `<scenetrans>`+声音连续、结尾截断 `<cutoff>`；相邻镜头人物不得变年龄/声音/服装/视线方向。

**（g）声音系统规范**（我方连播环节空白处）：soundscape 三层分离（环境声/动效/非叙事音乐）；**母音轨绑定**（一首 Master Audio 全程绑定，逐段弃用生成音频、剪辑对齐母音轨）；切点落拍（歌词停顿/军鼓/drop，1/4 或 1/8 拍格）；对白下 BGM ducking。

**（h）风格词汇锁定 + 光感十项继承**（光感小清新 skill）：项目应有自己的「视觉词汇表」（一组固定描述词全片逐字复用）；跨镜光线继承清单十项（主光方向/顺侧逆/色温/halation 程度/暗部亮度/肤色处理/背景色/景深柔焦/风向动态），续写逐项继承，前镜冷白强逆光后镜不得无故变暖黄顺光。
→ 我方「画质三档」是参数档，缺的是这种「项目级视觉词汇表」。

**（i）「未完成瞬间」原则**（生图 skill）：每张底图应含「下一秒即将发生变化」的未完成情绪瞬间——帧描述停在将变未变的时刻，i2v/flf2v 才有运动起点；且「图片识别以最终实图为准，原提示词不作数」——挑帧后视频提示词应以挑中的实图为准重写。

**（j）双稿架构**（打斗 skill）：中文导演母稿（人审对象）+ 英文模型执行稿（生成对象），编译只继承不改写，「英文新增内容必须先回写母稿，回写不了就删」——防编译过程偷偷改戏。

**（k）QC/fallback 阶梯**：成片级 QC 二元判定清单（对照锚点表逐项验收）；失败升级策略不是换种子重抽——①引用锚点原文强化提示词 ②缩短到 6s 以下（不稳定镜头安全上限）③拆分时长给相邻镜。

**（l）模板热插拔机制**：目录即方案（guide.md + meta.json + references/），建目录刷新即生效不改代码；manifest 注册表防错位；**我方模板硬编码在 TS 里，可改为文件系统方案包 + 注册表**（用户可自建/导入/分享模板）。

### 3.2 SKILLS 插件核心发现（提示词工程引擎）

**（a）H3 官方六段式提示词格式**——H3 原生投喂结构，我方 `buildLocalVideoPrompt` 未采用：

```
subject_definitions: <Subject 1> = 角色A外观锁定（可复用主体定义）
summary: [Subject 1 + Subject 2] 关系组合开头的一句话概括
retention_analysis: <Picture 1>: fully_preserved - 解释（每个参考素材的保留度声明）
detailed_description: 动作优先、按时间线、[Shot 1] 分镜标记（Shot1 无时间戳后续递增）
overall_soundscape: 环境声/动效层
non_diegetic_music: 非叙事音乐层
```

配套硬约定：对白 `<d>[Chinese]原文</d>`（语气/音色/语速写在标签外）、说话人 `(S1)(S2)` 按发声顺序编号、素材标签 `<Picture N>/<Video N>/<Audio N>` 先定义后引用、FL2VA 模式必须含裸 token `picture 1`/`picture 2`（首尾帧锚点声明，不许尖括号）、画外声必须跟闭口证据（"嘴唇始终完全闭合"）。

**（b）H1-H12 机检表**——纯规则质检（零模型成本）：字段完整性 / Shot1 无时间戳且递增 / 时长 4-15s / 语言标签 / 标签先定义后引用 / 保留度标记合法 / (Sx) 编号 / **否定式泄漏检测** / 画外声闭口证据 / 声音三层分离 / 语气位继承 / 首镜单主体。
→ **可整表搬进 App 做生成后自动质检**，挂在拆镜头输出与视频 prompt 组装两个出口。

**（c）否定式禁令铁律**：视频模型对否定不敏感、对词根敏感——"不要出现 X"会渲染出 X。改法三选一：换词根 / 正向描述 / 删触发词。我方 prompt 模板（如"无文字水印"）需全量复查这类写法。

**（d）284 个 T8 Creative DNA 机制库**：每个 = 机制 + 不变量（Rule/Purpose/Failure-if-removed 三元组）+ 可变槽位 + 中文摘要 + 预览 GIF。分类：微表情（表情校准/微表情问候）、叙事结构（人物旅程/威胁接力反转/倒地翻盘）、打斗（体型差格斗/非对称突破）、多段连续性（日程闭环/多人商品一致性）、镜头机制（景别收紧/深渊横移揭示）。
→ App 的「分镜机制库」种子：用户选机制 → App 填槽位（角色/场景/道具）→ 不变量保下限。`preview_manifest.json`（中文名+摘要+GIF+质量分）就是现成的模板库 UI 数据模型。

**（e）段缝末态双保险**（多段连续性，我方逐镜头生视频的痛点）：
- 每段提示词末尾强制写「接续状态 = 下一镜可直接开拍的画面」（谁+在哪+姿态+道具状态，禁"严格继承"套话）；
- 段缝强制换机位（禁同机位硬接）；切点不落在台词中间；
- **数据结构建议：`shot` 加 `end_state`（末帧画面描述）与 `next_anchor`（下一段首帧图）两字段**。

**（f）character-refs 单锚点派生体系**（角色一致性，Apache-2.0）：
- 一张正面全身锚点图为根，其余视图（大头照/90°侧/背面/细节×8/45°）**全部只参考锚点**——一致性来自同一锚点而非同一模型；任何一张出坏单独重出不连锁；
- H3 实测结论：只给正面全身图，脸会走样；**加一张大头照脸最接近**（我方设定图当前只有三视图全身，无大头照！）
- 冻结三样：锚点 sha256、画风快照、文字描述指纹——变了标"过期"但旧图保留（与 stale 机制同思路）。

**（g）h3-video-remake 防漂移三件套**（多角色镜头）：Ref2VA 而非 I2VA（I2VA 后半段角色漂移）；retention_analysis 每镜头标 fully_preserved；关键帧生成写 "Exactly N characters, each appears only once" 防多生成角色。

**（h）防 LLM 编造对白的工程手段**：`_remove_unsupplied_dialogues` 清除模型编造的对白 + `_ensure_supplied_dialogues` 保证用户台词恰好出现一次且嵌在时间线内——我方拆镜头的台词环节可复刻（纯正则+规则）。

**（i）工程架构借鉴**：
- 无模型降级：LLM 不可用时确定性模板 `build_fallback()` 输出结构完整草稿（三镜动作时间线：接触前→交锋→收束落帧）；
- 上下文预算分层：API 56k / 本地 18k 字符上限 + 头尾保留截断 + 按焦点只加载 3-4 个规则文件（我方拆镜头 system prompt 可按镜头类型动态加载对应规则包）;
- Skill = 文件系统 + front matter + ZIP 导入，零数据库热插拔——App 模板库可用同形态，便于导入分享。

### 3.3 AICG3D 主插件核心发现（生成执行层，v1.1.19，GPL-3.0）

三上游合并（MiniMaxH3-Easy 采样渲染 + goohai 提示词条件音频 + AICG3D 技能分段），约 40 节点全带 `AICG3D_H3` 前缀。核心是「智能短剧台」三件套：`SequenceGlobal`（全局分辨率/帧率/衔接帧数 5/22/39/56 档）+ `SequenceSegment`（每段独立提示词/秒数/种子/素材，链式无限增段）+ `SequenceCombine`（音视频拼接+接缝处理）。

**（a）提示词优化器（HTTP 直调，接入成本最低收益最直接）**
`POST /aicg3d/goohai/minimax-h3/prompt-optimizer/optimize`，body `{prompt, task, duration, media, context, request_id}` → 六段结构化提示词（含 `<d>[Chinese]</d>` 对白、picture 1/2 首尾帧锚点声明）。三层架构：任务感知系统提示词（六段/FL2VA 裸标签/对白时间线嵌入/替换模式专用规则）+ 双推理引擎（6 家云端 API 或本地 VLM/GGUF，推理前后卸载 ComfyUI 显存）+ **确定性后处理兜底**（补标签/正则抽台词保证每句恰好一次/格式修正——不信 LLM 自律）。
→ App 接法：注入 `<<PROMPT>>` 前先过这道优化器（可配通义/硅基流动国内 API 或本地 GGUF 零成本）。相当于给每个镜头配一个「H3 官方提示词工程师」。

**（b）无限段落 + 跨段衔接（我方逐镜头孤立生成的系统性解法）**
上段尾部 AV latent 直接当下段上下文（**无损续写**，非 RGB 再编码）；接缝运动桥（一帧姿态跳变过渡）；**跨段曝光锁定**（上段尾帧低频色光对齐 + 亮度平滑限幅）；最终链式合成 + 接缝检测报告。衔接帧数对齐 17n+5 栅格。
→ 即使不装节点，「latent 续写 + 曝光锁定 + 栅格对齐」三思路可移植进我方镜头拼接逻辑。

**（c）latent 3D 上采样 + SelfLift（W1 接力超分的原理细节）**
纯 3D 卷积重采样器直接放大 H3 24 通道 latent（时间轴不动只放大空间）；**放大倍率是条件输入——一个模型支持 1.0-4.0x 连续放大**（目标模式：倍率/宽高最大 8192/兆像素 0.1-16MP 即 4K）；>24 latent 帧自动分块重叠混合，显存有界。SelfLift 策略：前 N 步低分辨率 → learned lift（本模型）+ pixel lift（VAE 往返锚）按风险分位混合 → 后段全分辨率续采。

**（d）多参考系统（Ref2VA 标签体系）**
参考图 ≤9 / 参考视频 ≤3（重采样到 17n+5 帧、每 0.5s 抽帧、可绑原声）/ 独立音频 ≤3；**参考图双路注入：CLIP 视觉通道 + VAE latent 通道**（Qwen3-VL 类多模态文本编码器也看得到参考图）；标签校验（引用不存在的素材直接报错而非静默忽略）+ media_map 报告。配套 **YOLO 锁脸**：参考图脸检测抠出→羽化贴到关键帧人脸位置，身份像素级锚死（解决「换了参考图但脸不跟」）。
→ 与 11-10 部署清单里「H3 r2va 多参考（≤9 图）做多角色一致性」的既定方向互证；我方 ref2v 通道曾撤下（ref2va 模型 9.3G 停删），若重启需评估 Singularity/hybrid 底模。

**（e）H3 原生音频高级能力（我方仅用到基础生成，见诚实对照）**
我方现状：workflow 已带 audio_vae + VAEDecodeAudio（H3 Flash fl2va 原生音频），`buildLocalVideoPrompt` 有 `<d>` 与 Audio 行——**基础音频已有**。未用的高级层：`lock_source` 音轨锁定（TTS/配音音轨 denoise=0 锁死驱动口型——数字人模式）、`mix_audio` 对白闪避+峰值限制（现成混音器）、`clean_generated_audio_start` 生成音频开头爆音 RMS 检测修复、双时钟采样器（shift_video=12/shift_audio=2 修音画同步）、四种 audio_mode（native/lock_source/reference_only/remix_source）。

**（f）次级能力**：3D 白模动作迁移（SAM3+SAM3DBody 真人视频→白模骨架→H3 换人，颜色 ID 锁多人身份）；MotionCache+SageAttention 加速；`/api/media/validate` 素材预校验（防占位符注入后队列跑一半缺文件——思路小但省心）；分段剧本正则拆段（第N段（X秒）→ 逐段节点）；WebSocket 渲染阶段进度（sample/upscale/decode+预览图）。

### 4.2 对我方链路的直接借鉴（按价值排序）

**W1：接力超分替代多档独立生成（对照我方画质三档）。** 我方 high/standard/draft 三档各自独立采样；工作流 3/7 的做法是「低清出动态(5步) → latent 3D 放大 → 低噪声段补采(5步)」——动态稳定性与总耗时都优于高档直接生成，因为大部分算力花在低分辨率、且动态在低清段已锁定。配套关键：sigma 表拆两段（一采 [1.0→0.57]、二采 [0.90→0]）、二采独立噪声种子。**可作为画质三档的下一代实现**（当前 SeedVR2 是像素域事后超分，接力是 latent 域原生高清）。

**W2：帧数公式 n%17==5 三套工作流通用**——我方 `framesForDuration` 已等价实现 ✓（唯一差别：社区公式暴露在 UI，我们封装在代码，更安全）。

**W3：结构化多参考 prompt 全文模板（工作流 2/3/7 的 5378-12509 字符实文）。** 与第三节六段式互证。特色增量：
- `speaker_voice_mapping`（S1→独立生成声，S2→`<Audio 1>` 音色绑定）——**声画分角色映射**，多角色对白镜头直接可用；
- 节点 213 的「给任意 LLM」生成规则：输出五段结构（风格总览→时间线分镜→剪辑规范→音频→文字规范）+ 音频三用途（背景乐原样播/对口型逐字贴合/重拍剪辑依据）+ 占位符编号规则（序号按类型各自从 1 起）——**可直接作为我方拆镜头 LLM 的 system prompt 补充层**。

**W4：服装库闭环（工作流 4+6）。** 一句人设 → LLM 扩 N 套服装 → 白底商品图批量生图 → 「图1 角色换图2 衣服」自动换装。对照我方 D 项决策（角色妆造变体系统 ❌ 不做）：当时的否决理由是「完整变体系统属过度设计」，但工作流 4 证明轻量版（服装库挂角色卡，分帧 prompt 里指定服装编号）在 Qwen-Edit-2511 通道上几乎零增量成本——**值得重新评估为「角色卡 + 服装库」轻量形态**。换姿势库同理（分镜多样性）。

**W5：「逐项声明保留什么」的编辑 prompt 写法（工作流 6）。** 「将 image1 女子的服装替换为 image2…女子的长相、发型、表情、姿势和画风保持 image1 一致；保留双臂、双手及每根手指原有位置…保留背景光线构图」——比我方 refMode 的「保持图1中X的外貌完全一致（毛色/五官/体型/服装一项都不改）」更细（**手指位置/背景/光线逐项保留**）。refMode 模板可吸收。

**W6：RelayVSR 1 步 4× 视频超分。** 成本≈1 个 KSampler 步（对照 SeedVR2 需完整跑一遍模型）；x2/x4 模型文件已在资料夹（.qkdownloading 未下完状态，需补下）。可作为超分通道备选，与 SeedVR2 对比实测。

**W7：turbo sigma 表移植。** `[1.0,0.978,0.954,0.927,0.895,0.845,0.705,0.415,0.15,0]` 10 段 ManualSigmas（Qwen 系 turbo 家族，与我方 Z-Image-Turbo 同族）——我方 Z-Image 生图 workflow 若提质可试。

**W8：一题双卷 A/B 视图（工作流 1）。** 同 prompt/seed 双通道并行+拼图+标签——App 内做「重roll 对比」「换风格对比」的质检视图可借鉴。
