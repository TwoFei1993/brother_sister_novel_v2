# M2+M3 全后台生成 + 多书同步 实施计划

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 章节生成全链路 server 后台化（关页面跑完）+ 流式回流 + generation 多槽化 + 书架多书同步批量生成；完成后按设计共识「四、验证方案」做深度测试。

**Architecture:** ① 纯内核（engine/lib 树，已验证零 api/store/DOM 依赖）同构搬迁 shared 包，client 旧路径留 re-export shim（既有 import/测试零改动）；② server 新增 `services/novel-gen/`（组装 IO 注入 + 章节编排移植）与 `novel-chapter` 任务类型（复用 tasks 纯文件状态机，扩展 kind/workId/progress/cancel）；③ 客户端 generation store 多槽化 + 任务轮询回流（offset 增量，打字机视图复用）；④ 书架批量 = 每本书一个多章任务，server 全局并发编排器（默认 2）+ 同书互斥 409。依据共识 D4–D9。

**Tech Stack:** Express 4 + tsx（ESM 直跑源码，`@shared/*` paths 跨包直引）+ React 19 + zustand + vitest。

**测试命令**：client `cd v3/client && npx vitest run [path]`；server `cd v3/server && npx vitest run [path]`；shared `cd v3/shared && npx vitest run`。

1. **TaskFile 扩展**（向后兼容——旧字段全部保留，新字段全部 optional）：

```ts
interface TaskProgress {
  chapterIndex: number;  // 当前章（1 起）
  chapterTotal: number;  // 任务总章数
  phase: 'assembling' | 'generating' | 'continuing' | 'polishing' | 'saving';
  text: string;          // 当前章累计正文（换章重置；节流 1s 落盘）
  done: number;          // 已完成章数
  updatedAt: number;
}

interface TaskFile {
  // ...现有字段不动...
  kind?: 'llm' | 'novel-chapter';       // 缺省 'llm'（旧任务文件无此字段）
  workId?: string;                       // novel-chapter 专属
  cancelRequested?: boolean;             // 取消标志：段间/章间生效（当前段跑完即停）
  progress?: TaskProgress;               // 执行期增量；终态置 undefined
  resultMessages?: number;               // 终态：本次任务入库章数（done 时有）
  resultMessageIds?: string[];           // 终态：入库消息 id 列表（客户端同步本地视图的唯一依据）
}
```

2. **提交 schema 拆分**：`createSchema = z.union([llmTaskSchema, novelChapterSchema])`。`llmTaskSchema` = 现有 createSchema 原样；`novelChapterSchema`：

```ts
const prefsSchema = z.object({
  source: sourceSchema,
  model: z.string().min(1),
  temperature: z.number().optional(),
  maxContext: z.number().optional(),
  maxTokens: z.number().optional(),
  thinking: z.boolean().optional(),
  polishModel: z.string().optional(),
  frequencyPenalty: z.number().optional(),
  presencePenalty: z.number().optional(),
  repetitionPenalty: z.number().optional(), // 治重复循环三道防线之二（claude/MiniMax 通道）——漏传会导致 server 端生成行为与客户端漂移
});
const novelChapterSchema = z.object({
  kind: z.literal('novel-chapter'),
  workId: z.string().min(1),
  prefs: prefsSchema,
  mode: z.enum(['chapter', 'swipe', 'continue', 'append', 'expand']).default('chapter'),
  directive: z.string().default(''),
  chapters: z.number().int().min(1).max(50).default(1),
  outline: z.boolean().default(false),   // true=第 2..N 章用 OUTLINE_DIRECTIVE（按大纲链）
  targetId: z.string().optional(),       // swipe/append/expand 目标消息 id
  partial: z.string().optional(),        // continue 半成品基底
});
```

3. **同书互斥（D7 权威层）**：POST 提交 novel-chapter 前，扫 `TASKS_DIR` 全部 `*.json`：存在 `kind==='novel-chapter' && workId 相同 && status∈{pending,running}`（**含 cancelRequested=true 的取消中任务**——取消最多等当前段跑完（几十秒），期间重提交会产生双任务竞态，安全第一）→ `res.status(409).json({ code: 'GEN_BUSY', message: '该书已有生成任务进行中' })`。

4. **POST `/:id/cancel`**：读任务文件 → 若 pending/running 则置 `cancelRequested: true` 落盘 → `{ ok: true }`；终态任务 → `{ ok: false }`。

5. **GET `/active`**：扫目录，返回 `{ tasks: Array<{ id, kind, workId?, label?, progressLen, done, chapterTotal, phase, createdAt }> }`（仅 status∈{pending,running}；`progressLen = progress?.text.length ?? 0`）。**路由注册顺序**：`/active` 必须在 `/:id` 之前。

6. **GET `/:id` 扩展**：running 且 `?since=N`（query 整数 ≥0）→ `{ status:'running', label, progressLen, progressText: progress.text.slice(N), done, chapterTotal, phase, chapterIndex }`；无 since → 现有 `{ status:'running' }`（向后兼容，旧消费方不变）。**终态 + since** → 返回终态响应原样（status/text/error/label）+ 附加 `resultMessageIds: string[]`（TaskFile 终态新字段：本次任务入库的消息 id 列表，D9 文件唯一事实源——客户端多章任务完成后按 id 批量 `GET /api/works/:id/messages` 同步本地视图，不依赖 tail 窗口猜测）。
