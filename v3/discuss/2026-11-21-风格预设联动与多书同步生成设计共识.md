# 风格预设联动 + 多书同步生成 设计共识

> 2026-11-21 定稿。本文档为本功能唯一设计起点。
> 用户原始需求四点：① 每本书资料里可调写作风格；② 风格决定调用哪些酒馆预设（通用常驻，其余按情况选，tag 区分）；③ 选好后让用户确认；④ 多本书同步生成章节。

## 一、现状结论（调研依据）

前三个需求的核心已在最近提交落地（`68ea5c6` 预设打 tag + 按风格挂预设、`9dd4630` tags 断链修复）：

| 已有 | 位置 |
|---|---|
| 风格枚举 + 自定义描述 | `shared/src/work.ts` `WritingStyleSchema`（default/qidian/jjwxc/fanqie/custom）+ `NovelSettingsSchema.writingStyle/customWritingStyle` |
| 预设 tags + 编辑器 | `shared/src/preset.ts` tags 字段；`library/prompts/PresetTagEditor.tsx` |
| 风格→预设关键词匹配推荐 | `workbench/StylePresetSection.tsx`（tagMatches 双向子串） |
| 确认应用（保存层） | `StylePresetSection.tsx`「确认应用（风格+预设）」独立 PATCH |
| 生成期叠加注入 | `hooks/generation-pipeline.ts` `mergeStylePresets`（追加主栈尾部，identifier 加前缀） |

**确认的缺口**：
1. 建书时（NewWorkDialog）不能选风格，只能建后进设置抽屉改
2. 改风格/基调后**不重跑预设推荐**（useEffect 只依赖 work.id）
3. 匹配只看 tags 不看预设名称（「番茄欢乐」这类名字命不了中）；推荐无理由展示
4. 生成前无任何预设可见性（静默读已存 stylePresetIds）
5. **多书并行完全缺失**：generation store 全局单槽（`streaming` 单值 + 防重入），batch 循环严格串行
6. server `/api/llm/tasks` 只代理**单次** LLM 调用（组装/分段/finalize 全在客户端，页面关闭链路即断）；任务执行期增量直接丢弃，无回流

## 二、设计决策

- **D1 补强不重做**：保留现有 StylePresetSection / tagMatches / mergeStylePresets 架构，修缺口不推倒。
- **D2 匹配范围扩展**：推荐匹配看 tags + 预设名称（双向子串包含），「欢乐向书 → 番茄欢乐预设」这类名称命中也能推荐。
- **D3 非通用预设的用户确认放保存层**：「确认应用」升级为确认弹窗（通用默认勾选常驻 / 匹配预设预勾选并展示推荐理由「命中：××」/ 其余可手动补选）。**不做生成期确认、不做生成期强制注入**——用户明确取消的预设不偷偷加回。
- **D4 全后台 + 流式回流**：所有章节生成统一走 server 端任务（书页发起与书架批量同一链路），书页通过增量回流实时渲染流式输出；关浏览器页面 server 继续跑完并落库。
- **D5 纯内核下沉 shared，IO 缝注入**：`scanAndAssemble` 整体**不是**纯函数（内部含滚动摘要 LLM 调用、`/api/tokenize` 调用、摘要落库 PATCH、从 store 读全局变量）。下沉 shared 的是纯内核子函数：`scanWorldInfo / assemblePrompt / planContext / novelGuardPlan / recallBlock / skeletonBlock / pickChapterRequirement / postprocess`；IO 缝（token 计数、预设/资产加载、摘要器、全局变量、落库）由调用方注入——client 版维持现有实现，server 端编排层（含 `mergeStylePresets` 的 server 版）各自实现注入。客户端既有测试继续有效，避免两份实现漂移。
- **D6 server 端章节任务**：新增 `novel-chapter` 任务类型，server 执行完整链路（组装→分段→截断续写→finalize→persistMessage 直接落库 messages.jsonl/work.json）。多章连续生成时下一章从 server 真数据组装，天然衔接。
  - **失败语义**：章内单次 LLM 调用沿用现有三级防线（瞬态退避重试→预算加倍→灾备通道）；防线耗尽仍失败 → 任务标 failed，**该章不入库（半章残文丢弃）**，已入库的前几章保留，书停在 N/M 章，书页/书架卡片显示失败态 + 可单本重试（从失败章续跑）。与现状客户端行为（出错即停、已入库保留）一致。
  - **取消语义**：「单本取消」在段间生效（当前段跑完即停），半章残文丢弃不入库，书停在已入库的最新章。
  - **执行中删书**：下次写盘时校验 work 不存在 → 任务中止标 failed（删除/改名执行前校验同样保留）。
- **D7 多槽并发 + server 权威互斥**：generation store 按书隔离（`Record<workId, GenSlot>`，客户端预检快速反馈）；**互斥权威层在 server 提交层**——同一 workId 已有活跃 novel-chapter 任务时 POST 返回 409（防双端/双入口竞态）；书间并发默认 2（可调 1–4，批量弹窗内设置；书页发起与批量同受同一 server 编排器并发上限约束），超出排队。
- **D8 书架批量发起**：书架多选 → 「同步生成」→ 设每本章数 + 并发数（默认 2，可调 1–4）→ server 端编排逐本逐章；卡片实时进度 + 单本取消/重试。批量发起前**不**再弹预设确认（用户已在保存方案时确认过）；`stylePresetIds` 为空/从未确认过的书按主预设（无附加预设）直接生成。
- **D9 任务文件扩展**：TaskFile 加 `kind`（llm | novel-chapter）、`workId`、执行期 `progress = { chapterIndex, phase, text, updatedAt }`（节流 1s 增量落盘；phase 标注 组装/分段生成/截断续写/后处理/落库）。文件仍是唯一事实源，回流用轮询增量（客户端带 offset 切片拉取）——SSE 为后续可选优化，本轮不做。
- **D10 验证用 sample 深度实测**：见「四、验证方案」。

## 三、实施内容

> 实施拆分：M1 与 M2+M3 几乎无共享代码，planning 阶段拆两个计划（M1 一份、M2+M3 一份）；本次全部实施完成后统一深度测试。

### M1 风格与预设链路补强
1. `NewWorkDialog` 加写作风格下拉（默认经典网文），创建后书页提示去确认预设
2. StylePresetSection 推荐重跑：useEffect 依赖扩展为 work.id + writingStyle + storyTones + genre；保留已勾选项，新推荐打标记
3. 确认弹窗：三分组（通用/匹配推荐+理由/其余）、匹配含预设名称、非通用必须经确认写入 stylePresetIds

### M2 全后台单书 + 回流基建
1. 纯内核下沉 shared（D5 清单：scanWorldInfo/assemblePrompt/planContext/novelGuardPlan/recallBlock/skeletonBlock/pickChapterRequirement/postprocess）；server 端新增 novel-gen 编排层（IO 注入 + `mergeStylePresets` server 版）
2. TaskFile 扩展（D9）+ `GET /api/llm/tasks/active`（活跃任务摘要，书架轮询用）+ 提交层同书互斥 409（D7 权威层）
3. `novel-chapter` 任务类型：server 端完整章节链路（失败/取消/删书语义按 D6）+ progress 增量落盘
4. 书页发起切换为提交 server 任务；书页对活跃任务轮询增量（offset 切片）渲染流式
5. generation store 多槽化（per-work 预检），书页互不阻塞，顶栏「后台生成中 N 本」

### M3 书架批量 + 深度验证
1. 书架多选 + 批量发起弹窗（每本章数、并发数默认 2）
2. server 端多章编排（逐本逐章，队列并发，单本取消/重试）
3. 深度验证（见下节）

## 四、验证方案（用户要求：全部完成后深度测试，用 sample）

1. **单测**：tagMatches 扩展（tags+名称）、推荐重跑逻辑、多槽 store、任务 progress 增量协议
2. **deep-test-author-50.mjs 扩展**：tasks/active 新端点用例、novel-chapter 任务提交/进度/取走链路、A 书生成中 B 书可发起的并发场景、同书互斥（**server 层断言**：同 workId 第二次提交返回 409）、章失败不入库且已入库章保留
3. **sample 端到端实测**：建两本书（含 `_sample_chapter.txt` 风格兄妹题材书）同时批量生成，验证：① 流式回流渲染正常；② 预设按 tag 正确注入（检查组装产物）；③ 关浏览器后 server 继续跑完并落库；④ 并发数上限与排队正确
4. **既有回归**：client 全量测试 + `verify-*.mts` 冒烟 + 预设相关既有单测

## 五、风险与边界

- **组装管线迁移回归风险**（生产实测修出的稳定性机制多）：靠「纯内核下沉 shared + IO 缝注入（D5）+ 既有测试全绿」兜底——迁移是搬不是改，编排与 IO 在 server 侧新写
- **LLM API 限速**：书间并发默认 2、可调 1–4；单书内分段仍严格串行（现状不变）
- **任务丢失**：server 重启 → lost，书架可重新发起；书删除/改名 → 执行前校验 + 执行中写盘校验（D6）
- **移动端**：App 切后台 JS 冻结不影响（server 后台执行）；书架批量在移动端同样可用
