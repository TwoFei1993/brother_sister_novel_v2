# 短剧：试验台与分集剧本

> 2026-11-26 交付。设计依据：`discuss/2026-11-26-短剧试验台与分集剧本设计.md`、`discuss/2026-11-26-试验台增强M2设计.md`。
> 本文讲怎么用、哪些行为是刻意的、改代码时别踩的坑。总览见 `短剧功能说明.md`。

## 一、试验台（测试生图）

**入口**：短剧工作台的「试验」分区。不受「剧本定稿」锁，手机、桌面、App 一套界面。

**流程**：输入一句话 → 「生成完整提示词」（AI 扩写）→ 在审批区改 → 「确认出图」→ 进历史。

| 区块 | 说明 |
| --- | --- |
| 画面类型 / 通道 / 画幅 / 语言 | 通道默认跟随设置页，试验台里可以临时切，不影响正式出图 |
| 画风 | **跟随作品画风**——短剧工作台「角色」分区顶部的画风芯片（动漫风/3D 卡通/写实/国漫/水墨）就是开关，建书时的「画风」芯片是同一字段；试验台扩写自动带上当前画风 |
| 带入设定 | 点选角色、场景，它们的档案进扩写消息。不会自动把设定图加成参考图 |
| 参考图 | 上传图片、从本作品的角色设定图 / 场景图里选、或在历史详情里「设为参考图」 |
| 审批区 | 可编辑；超过该通道的字数上限时禁止出图并提示删减，**不截断** |
| 历史 | 复制、下载、再出一张、回填修改、设为参考图、删除 |

### 参考图的规矩

- **本地引擎 0–3 张，Seedream 1 张，GLM-Image 不支持。**
- 顺序就是 Picture 序号，**第 1 张是底图**（场景、构图、造型跟它走）。要换底图就删掉重加。**底图质量直接决定出图质量**——拿随手生成的图当底图，出图也会差。
- 每张写一句说明。扩写模型看不到图，全靠这句话知道每张图画的是什么。从作品里选的会自动填。
- 切到上限更小的通道不删图，只是少用：超出的标灰并写「该通道不会用」。

### 分辨率

- **本地引擎 8MP 档**（2026-11-27 起）：9:16 = 2016×3584，16:9 = 3584×2016，1:1 = 2688×2688，4:5 = 2400×3008——与 H3-Image 生成管线的分镜档同源。单张约 2–5 分钟。
- 此前是 768×1344 小图档（约 1MP），出图细节密度不足；已按用户裁定整体升档。
- 云端通道尺寸由上游服务商决定，不受此档影响。

### 两条刻意的约定

1. **审批的就是送去生成的。** 审批区锁住「扩写那一刻」的参数（通道、画幅、参考图、带入的设定），并写明了锁定的通道与画幅。之后改输入区不影响这次出图；想换参数就点「重新扩写」。
2. **出图中途可以走开。** 本地出图提交成功那一刻就记下引擎任务号；切到别的分区、离开作品再回来、甚至刷新页面，都会接着等并归档，已用时长不归零。扩写同理（走的是服务端后台任务，按作品隔离）。云端出图是一次性请求，切走就中断，回来重点一次即可。
3. **试验记录独立于作品版本号**：增删试验图不会让别的分区出现「版本冲突」。历史最多留 300 条，超出时淘汰最旧的（连同它的图）。

### 存哪儿

- 记录：`data/works/<id>/duanju/lab.json`，与 `project.json` 分开，**不参与作品版本号**。
- 图片：`duanju/images/`，参考图的文件名带 `labref-` 前缀。
- 删除记录会连带删除它的图；参考图被别的记录共用时不删。上传后一直没出图的参考图，2 小时后自动清理。

## 二、分集剧本

**每集有自己的剧本正文，拆镜头只读本集。** 在此之前每集只有一句梗概，拆镜头时把全文喂给模型让它即兴发挥，集与集的边界只靠梗概约束。

### 剧本分区里的分集剧本区

| 操作 | 说明 |
| --- | --- |
| 原文性质 | 「整本小说」→ 各集从原文改编；「只有第 1 集」→ 第 1 集直接用原文，第 2 集起续写。自动推断，可手改 |
| 一键改编全部未写集 | 只跑分集剧本，写完即停 |
| 单集卡片 | AI 改编 / AI 续写 / 按要求重写 → 先出草稿 → 「保存并采用」才落库。重写后保存不改来源；在编辑器里直接改了再保存记「手写」；把内容删光再保存等于清除这一集的剧本（会先确认） |
| 停靠开关 | 打开后，自动流水线写完分集剧本就停下等你审，再点「继续拆镜头」 |

### 自动流水线

**什么时候启动**：一键转短剧后的自动拆解完成、手动「AI 拆解」完成。

**顺序**：角色档案 → 场景档案 → 分集剧本（逐集）→ 拆镜头（逐集）。角色和场景放前面，是为了写剧本、拆镜头时名字一致。

**几条规则**：

- **不覆盖已有内容。** 角色档案已有非空的不动，只补缺失的；某集已有剧本的跳过；某集已有镜头的跳过。流水线跑的过程中你在别处写了哪一集、加了哪个镜头，同样以你的为准——每一集开始前都会重读作品，写入前还会再确认一次。想刷新用卡片上的「重写」，想重拆去分镜分区手动点。
- 某一集写失败不中断，结束时汇总「第 X 集失败，可重试」。
- **断网或额度用尽时整个停下来**（不会把剩下的集挨个记成失败），保留断点，恢复后点「重试」接着跑。
- 顶栏下方有进度条和「停止」。点停止：当前这一步跑完后停下，之后不再自动续跑。
- 页面被回收或刷新属于被动中断：下次打开这个作品自动接着跑。续跑的范围和中断前一致——「一键改编」中断了，续跑也只写剧本，不会自己接着拆镜头。
- 生成成功但没保存上（比如版本冲突）的，重试时直接取回已生成的那份，不重新花一次调用。
- 流水线运行期间，「AI 拆解」「AI 生成剧本」「AI 拆镜头」「一键改编」「单集 AI 改编 / 续写 / 重写」会暂时禁用；编辑、保存、出图、导出不受限。停靠等你审的时候，单集的 AI 按钮可以用。

### 改了剧本之后

改了某一集的分集剧本并保存，这一集已经出图的镜头会标「待刷新」。别的集不受影响。原文内容没改的保存不会刷新更新时刻。

### 导出

剧本 TXT 每集带本集剧本；导出包的镜头表多一节本集剧本。

## 三、改代码时别踩的坑

- **服务端请求体是严格校验的**（zod `strictObject`）。内部对象不要整个当请求体传——多一个字段就是 400。新增字段要同步改 `shared` 里的 schema。
- 参考图路径有白名单（`LAB_REF_PATH_RE`，只认 `labref-` 前缀）。服务端读盘、删文件前都只取文件名再拼进作品图片目录。
- 工作台的各分区是常驻挂载的（用显示 / 隐藏切换，不再卸载重挂），否则批量出图每刷新一次就会把编辑中的内容弄丢。副作用是进入工作台时各分区都会发自己的加载请求。
- 试验台本地出图带参考图时用专用模板（采样器 `euler`）；没有参考图时走设置页生效的文生图模板。
- ComfyUI 浏览器直连用到的接口：`/system_stats`（内存余量）、`/free`（紧张时释放缓存）、`/upload/image`、`/prompt`、`/history/<id>`、`/view`。提交和轮询是两段，中间靠任务号衔接。
- 短剧资产库的接口路径是 `/api/duanju-assets/…`（服务端把 libraryRouter 挂在 `/api` 下，**没有** `/library` 一层）。

## 五、已知边界

- **带参考图的专用工作流没在真引擎上出过图。** 只在测试里对着假引擎核对过提交内容（槽位裁剪、采样器 euler、占位符替换）；节点定义与引擎里登记的对得上。交付当天两次想实测，引擎都被别的会话占着。**第一次用请先拿一张图试**；失败的话看页面上的人话报错。
- **Seedream 带参考图**只有单测覆盖（请求体里有参考图），没有实测——花钱的操作不自动跑。
- **场景档案会带后面的剧情。** 流水线提取场景读的是全文，会把故事结尾的道具状态写进档案；拆镜头又把档案当「视觉基调」拼进每一集的镜头画面提示词，于是前面集数的画面里可能出现后面才出现的道具（实测时第 1 集的 12 个镜头都带着第 3 集结尾的「火车票、辣椒罐」）。镜头本身的动作和台词不串。怎么改待定：建议场景提取只写不随剧情变的结构，道具以本集剧本为准。
- **内置文生图模板与官方规定有出入**：采样器是 `SamplerLCM`（官方与 11-24 实验定稿都是 `euler`），文本编码器是 `nvfp4_awq`（官方模板用 `int8_convrot`，参考图是经它看进去的）。试验台里两者并存：带参考图用 euler，不带参考图沿用内置模板。是否统一待定。
- **试验台的扩写规则里，依据官方提示词技能补的部分没有实测**：没有文字要求时写一句「图中没有任何文字、字母或数字」；带参考图时每个主体单独一句关系。官方建议提示词用英文写，试验台默认中文（输入区有语言开关）。
- **出图等待超过 15 分钟**按「等太久」处理：检查点保留，回到试验分区会自动再续一次；只有引擎明确说任务丢了才清。
- 云端出图是一次性请求，切走就中断，回来重点一次。
- 参考图不支持拖拽排序；上传后 2 小时内没出过图的参考图会被清理（界面上还在的图出图时会提示重新添加）。
- 从备份恢复导致服务端版本比界面低时，冲突条上的「刷新」不生效，需要整页重载。
- 分区常驻挂载后，进入工作台时各分区都会发自己的加载请求。
