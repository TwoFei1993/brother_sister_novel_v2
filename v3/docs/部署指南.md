# v3 部署指南

> 生产部署唯一路径：**Zeabur 两个服务**——本主服务（Express 同源托管前端与 API）+ 既有 easyvoice TTS 服务，固定域名，废弃 cpolar。Dockerfile 兜底，不锁死 Zeabur。
>
> 本文所有结论均对照当前实现核对过：标「生效」的是真实读取的配置；标「预留」的是设计清单中存在、但当前版本**未实现** env 预读的项——这类配置走 `/settings` 页面录入。

---

## 1. 环境变量清单

| 变量 | 必填 | 状态 | 说明 | 示例 |
|---|---|---|---|---|
| `ACCESS_PASSWORD` | **必填** | 生效 | 登录密码（单密码鉴权）。未配置时服务能启动，但登录接口返回 503，无法使用 | `my-secret-pass` |
| `AUTH_SECRET` | 可选 | 生效 | 登录 token 的 HMAC 密钥。不设置则进程内随机：**每次重启后所有人需重新登录**。多实例部署或希望重启不掉登录态时固定它 | `a-long-random-string` |
| `DATA_DIR` | 可选 | 生效 | 数据目录（作品/角色卡/世界书/密钥等全部落盘于此）。Docker/Zeabur 内固定 `/app/data` 并挂卷；本地默认 `v3/data` | `/app/data` |
| `PORT` | 可选 | 生效 | 监听端口。Docker/Zeabur 内固定 3001 | `3001` |
| `LOG_DIR` | 可选 | 生效 | 日志目录。Docker/Zeabur 内固定 `/app/logs`；本地默认 `v3/logs` | `/app/logs` |
| `LOG_LEVEL` | 可选 | 生效 | 日志级别（pino）：`info`（默认）/ `debug` / `error` | `info` |
| `OPENAI_API_KEY` + `OPENAI_BASE_URL` | 可选 | **预留** | 当前版本**不支持从环境变量读取**。登录后在 `/settings` 录入（OpenAI 兼容通道可自定义 baseUrl 接中转站），落盘 `data/secrets.json` | — |
| `GEMINI_API_KEY` | 可选 | **预留** | 同上：`/settings` 录入，env 预读未实现 | — |
| `ANTHROPIC_API_KEY` | 可选 | **预留** | 同上：`/settings` 录入（通道名 claude），env 预读未实现 | — |
| `TTS_BASE_URL` | 可选 | **预留** | 当前版本**不支持从环境变量读取**。登录后在 `/settings` 填 TTS 服务地址，落盘 `data/config.json` 的 `ttsBaseUrl` | — |

### 密钥与 TTS 的正确配置方式（主路径）

密钥不进环境变量，**登录后在 `/settings` 页面录入**，由服务端明文落盘到数据卷（仅服务端可读，任何接口不回传明文，只回布尔掩码）：

| 内容 | 录入位置 | 落盘文件 | 健康检查反馈 |
|---|---|---|---|
| LLM 密钥（openai / gemini / claude 三通道） | `/settings` 密钥面板 | `data/secrets.json` | `/api/health` 的 `llm` 对应通道变 `true` |
| TTS 地址（easyvoice 服务，含 `/api/v1/tts` 路径） | `/settings` | `data/config.json` 的 `ttsBaseUrl` | `/api/health` 的 `tts` 由 `unset` 变 `ok` |

以上数据都在 `DATA_DIR` 下，随 volume 持久化——**录入一次，重启/更新不丢**。

## 2. Zeabur 部署步骤

前置：GitHub 仓库已包含 `v3/`（含 `Dockerfile`、`zeabur.yml`）；easyvoice 服务已在同一 Zeabur 账号下运行。

1. **新建项目**：Zeabur 控制台 → New Project（选区域）。
2. **添加 Git 服务**：Add Service → Git → 选择本仓库。在服务设置的 **Root Directory** 填 `v3`。
3. **确认构建方式**：目录内存在 `Dockerfile`，Zeabur 走 Docker 构建（多阶段：builder 全量构建 → prod-deps 生产依赖 → runner 精简运行层）。构建日志可见三个阶段依次完成，最终 `CMD ["node","--import","tsx","src/main.ts"]`。
4. **配 Volume**（服务 → Volumes）：挂载两卷——
   - `/app/data`（**必配**：数据持久化，不挂则重启丢全部作品与密钥）
   - `/app/logs`（可选：日志落盘）
5. **配环境变量**（服务 → Environment）：至少 `ACCESS_PASSWORD=你的密码`；建议加 `AUTH_SECRET=<长随机串>`（防重启掉登录态）。
6. **配网络**（服务 → Networking）：暴露端口 `3001`（HTTP），绑定/生成域名。
7. **部署完成后自检**：浏览器打开域名应看到登录页；再核对健康检查（见 §4）。
8. **录入密钥与 TTS**：用 `ACCESS_PASSWORD` 登录 → `/settings` → 录入 LLM 密钥、TTS 地址。

### easyvoice 对接

TTS 走既有 easyvoice Zeabur 服务，无需重复部署。在 `/settings` 把 TTS 地址填成 easyvoice 的**公网完整地址**（含 API 路径），例如：

```
https://<你的easyvoice域名>.zeabur.app/api/v1/tts
```

填完回首页看 `/api/health`：`tts` 应变 `ok`（探针 3 秒超时内收到任何 HTTP 响应即算可达）。`down` 则检查地址拼写与服务是否在线。

## 3. 健康检查 `/api/health` 解读

免鉴权，部署后先看它。返回体三段：

```json
{ "storage": "ok", "tts": "unset", "llm": { "openai": false, "gemini": false, "claude": false } }
```

| 字段 | 取值 | 含义 | 处置 |
|---|---|---|---|
| `storage` | `ok` / `fail` | data 目录写入探针（写探针文件再删除） | `fail` = volume 未挂载或无写权限，**必须修复**，否则数据不落盘 |
| `tts` | `unset` / `ok` / `down` | `unset`=未配置 TTS 地址；`ok`=3s 内收到响应；`down`=网络层失败 | 未配置属正常；`down` 查 TTS 地址与 easyvoice 服务状态 |
| `llm` | 三通道布尔掩码 | `true`=该通道密钥已录入 | 全 `false` 是新部署的预期态；用到哪个通道录哪个 |

**全新部署的合格线**：`storage: "ok"`，`tts: "unset"`，`llm` 全 `false`——这三项即「环境可用」，其余属配置项未录入。

## 5. 备份与恢复

所有业务数据集中在 `DATA_DIR`（本地 `v3/data`，容器/Zeabur 为 `/app/data`）：

```
data/
├─ secrets.json          # LLM 密钥（敏感，勿外传）
├─ config.json           # TTS 地址 + 全局变量
├─ characters/           # 角色卡
├─ worldbooks/           # 世界书
├─ presets/              # 预设
├─ regex-scripts/        # 正则脚本
├─ works/<workId>/       # 作品（work.json 元数据 + messages.jsonl 消息流）
└─ backups/              # 备份产物默认落这里
```

**备份**（本地 / 能进 shell 的环境，在 `v3/` 下执行）：

```bash
bash scripts/backup.sh
# → 生成 backups/backup-<时间戳>.tar.gz（打包整个 data/）
```

**恢复**：在 `v3/` 根目录解包覆盖（解包后 `data/` 整体被还原）：

```bash
tar -xzf backups/backup-<时间戳>.tar.gz
```

**Zeabur 上的备份**：Volumes 面板可下载卷内容；或本地拉取镜像后把 volume 数据拷出（`docker run --rm -v novel-v3-data:/data alpine tar cz -C /data . > backup.tar.gz`）。建议定期备份并异地保存一份。

## 6. 常见问题（健康检查红项排查）

| 现象 | 原因 | 处置 |
|---|---|---|
| 登录接口 503「服务端未配置 ACCESS_PASSWORD」 | 环境变量没配或没生效 | 服务 → Environment 加 `ACCESS_PASSWORD` 后重启部署 |
| `/api/health` 的 `storage: "fail"` | Volume 未挂载 `/app/data`，或权限不足 | 检查服务 Volumes 配置；确认挂载路径精确为 `/app/data` |
| `tts: "down"` | TTS 地址填错 / easyvoice 服务没在线 / 网络策略拦截 | 核对 `/settings` 里地址是否含 `/api/v1/tts`；单独浏览器访问该地址确认可达 |
| `tts: "unset"` 且 `/settings` 已填 | 配置未保存成功 | 看 `/settings` 保存提示；确认 `config.json` 出现在数据卷 |
| 某通道 `llm: false` 但已录入 | 密钥面板保存失败（如 apiKey 为空） | 重录；`GET /api/secrets` 只回掩码，录成功即 true |
| 重启后全员掉登录 | 未设 `AUTH_SECRET`，token 密钥随机 | 加 `AUTH_SECRET` 环境变量并保持不变 |
| 首页白屏 / 静态资源 404 | 镜像内 `server/public` 为空（构建阶段失败） | 查 Zeabur 构建日志的 builder 阶段；本地 `bash scripts/build.sh` 复现 |
| 写作中 LLM 无响应 | 通道密钥未录 / 上游不通 | `/settings` 确认通道掩码为 true；`/api/health` 看不到通道连通性，属正常（密钥掩码≠连通探针） |

## 自有服务器部署（国内直连推荐，compose 生产编排）

前置：自有域名（A 记录指向服务器 IP，Cloudflare DNS 设「仅 DNS/灰云」——直连最快，橙云代理国内反而慢）、服务器装 Docker、开放 80/443。
⚠️ 服务器在国内云（阿里/腾讯）时，域名 80/443 需 ICP 备案（服务商强制）；海外服务器无此要求但延迟略高。

```bash
# 服务器上拿到编排与反代文件（或直接复制 docker-compose.prod.yml + Caddyfile.prod 内容）
DOMAIN=novel.example.com ACCESS_PASSWORD=你的密码 \
  docker compose -f docker-compose.prod.yml up -d
```

组成：Caddy（自动 HTTPS，证书全自动）→ 主应用（GHCR 镜像）+ easyvoice TTS 容器（音频落卷）。

部署后一次配置（/settings 页面）：
1. **LLM 接入**：录入真实通道密钥（或迁移旧环境 `data/secrets.json`）
2. **TTS**：地址填 `https://<你的域名>/tts` → 测试连通 → 听书即可用（easyvoice 用 Edge-TTS，服务器需能访问微软接口）
3. 数据迁移：旧环境 `data/` 目录整体拷入 `app-data` 卷对应位置后重启 app 容器

## 腾讯云 Linux 服务器部署（完整流程）

### 阶段 0：前置检查
- **域名备案**：大陆服务器绑域名走 80/443 必须已 ICP 备案（腾讯云会拦截未备案域名的网页访问）。未备案的替代：① 用 `IP:3001` 直接访问（compose 端口映射改 `3001:3001` 并去掉 caddy 服务，无 HTTPS）② 服务器换香港/海外区域（免备案）③ 提交个人备案（约 1-2 周）
- **防火墙**：腾讯云控制台 → 防火墙/安全组 → 放行 22 / 80 / 443
- **GHCR 拉取**：GitHub 仓库 Packages 页把镜像设为 Public（否则服务器 `docker pull` 401）
- **compose 插件**：服务器 `docker compose version` 能出版本号即可；不能则安装 `docker-compose-plugin`

### 阶段 1：取部署文件
```bash
git clone https://github.com/TwoFei1993/brother_sister_novel_v2.git
cd brother_sister_novel_v2/v3
```

### 阶段 2：配置并启动（三容器：caddy + app + easyvoice）
```bash
cat > .env <<'ENVEOF'
DOMAIN=novel.你的域名.com
ACCESS_PASSWORD=你的登录密码
ENVEOF
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps   # 三个容器均 Up
```

### 阶段 3：验证
浏览器打开 `https://域名` → 出现登录页 → 登录进入书架。

### 阶段 4：一次配置（/settings 页面）
- **LLM 接入**：录入真实通道密钥（若做了阶段 5 的 secrets 迁移则免）
- **TTS**：地址填 `https://域名/tts` → 「测试连通」→ tts=ok（服务器上跑的是真 easyvoice；本机 9911 的 mock-tts 仅本地测试用）

### 阶段 5：数据迁移（本机 → 服务器，作品/资产/密钥一次带走）
本机（Git Bash）：
```bash

```

```bash

docker exec novel-app sh -c "cd /app/data && tar xzf /tmp/novel-data.tgz && rm /tmp/novel-data.tgz"
docker compose -f docker-compose.prod.yml restart app
```
刷新页面：作品/资产/密钥全部就位。

### 阶段 6：上线自查
- [ ] `/api/health`：storage=ok / tts=ok / llm=true
- [ ] 生成一章 → 重启容器 → 章节仍在
- [ ] 听书出声（easyvoice 走 Edge-TTS，服务器需能出网访问微软接口）
- [ ] 手机直连域名可读可听（PWA 可装到桌面）

### 日常运维
- 更新版本：`git pull && docker compose -f docker-compose.prod.yml pull app && docker compose -f docker-compose.prod.yml up -d`
- 备份：定期打包 `app-data` 卷（`docker run --rm -v novel-prod_app-data:/data -v $PWD:/bak alpine tar czf /bak/data-$(date +%F).tgz /data`）

## 无域名快速上线（IP 直连，当天可用）

大陆服务器纯 IP 访问不需要备案。代价：HTTP 无证书（浏览器提示不安全，可继续使用）、PWA 安装不可用、地址不如域名好记。

```bash
# 腾讯云控制台 → 防火墙/安全组 → 放行 3001/TCP 和 9911/TCP
# GHCR 镜像设为 Public 后：
docker pull ghcr.io/twofei1993/brother_sister_novel_v2:latest   # 验证可拉取
docker run -d --name novel-app -p 3001:3001 \
  -e ACCESS_PASSWORD=你的登录密码 \
  -v novel-data:/app/data -v novel-logs:/app/logs \
  --restart unless-stopped \
  ghcr.io/twofei1993/brother_sister_novel_v2:latest
# TTS 引擎（听书用，真 easyvoice；本机 9911 的 mock-tts 仅本地测试）
docker run -d --name novel-tts -p 9911:3000 \
  -v novel-tts-audio:/app/audio --restart unless-stopped \
  cosincox/easyvoice:latest
```
访问 `http://124.222.187.155:3001` → 登录 → /settings：TTS 地址填 `http://124.222.187.155:9911` → 测试连通。

**升级到域名 HTTPS**（备案通过后）：DNS 加 A 记录 → 按「腾讯云 Linux 服务器部署」章节起 caddy 编排 → 数据卷 `novel-data` 与新编排的 `app-data` 二选一保持一致即可。

## 国内拉取慢的解决 + 自动更新

GHCR 在海外，腾讯云服务器直拉很慢。两个解决层：

**镜像加速地址（零配置，推荐）**：GHCR 包设为 Public 后，通过国内加速前缀拉取（实测：南京大学镜像 ghcr.nju.edu.cn，全镜像 48 秒拉完；DaoCloud 已不支持 ghcr 嵌套路径，勿用）：

```bash
# 原始：ghcr.io/twofei1993/brother_sister_novel_v2:latest
# 加速：ghcr.nju.edu.cn/twofei1993/brother_sister_novel_v2:latest（实测 48s）
docker pull ghcr.nju.edu.cn/twofei1993/brother_sister_novel_v2:latest
```

**自动更新**（cron 每 10 分钟检查，有新版才重建容器，数据卷不动）：服务器上一次性安装自动更新脚本后，加速地址写进 `/opt/novel/.env` 的 REGISTRY 即可：

```bash
sudo mkdir -p /opt/novel
sudo cp scripts/server-update.sh /opt/novel/
sudo tee /opt/novel/.env >/dev/null <<'ENVEOF'
REGISTRY=ghcr.nju.edu.cn/twofei1993
ACCESS_PASSWORD=你的登录密码
ENVEOF
sudo chmod 600 /opt/novel/.env /opt/novel/server-update.sh
sudo crontab -e   # 加入一行：
# */10 * * * * /opt/novel/server-update.sh >> /var/log/novel-update.log 2>&1
```

之后每次代码 push → CI 自动构建 GHCR 镜像 → 服务器 10 分钟内经加速源自动拉取更新，全程无需登录服务器。

> 备选：若需要镜像保持**私有**，用阿里云「容器镜像服务 ACR 个人版」（免费且支持固定用户名/密码）——CI 推送 ACR 需在 GitHub Secrets 配置 ACR 凭证（可参考 workflow 中 TCR 步骤的同构写法）；或升级腾讯 TCR 企业版。个人自用场景，Public + 加速源最省事。
