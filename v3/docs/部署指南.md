# v3 部署指南

> 生产部署唯一路径：**Zeabur 两个服务**——本主服务（Express 同源托管前端与 API）+ 既有 easyvoice TTS 服务，固定域名，废弃 cpolar。Dockerfile 兜底，不锁死 Zeabur。
>
> 本文所有结论均对照当前实现核对过：标「生效」的是真实读取的配置；标「预留」的是设计清单中存在、但当前版本**未实现** env 预读的项——这类配置走 `/settings` 页面录入。

---

## 1. 环境变量清单

| 变量 | 必填 | 状态 | 说明 | 示例 |
|---|---|---|---|---|
| `ACCESS_PASSWORD` | **必填** | 生效 | 登录密码（单密码鉴权）。未配置时服务能启动，但登录接口返回 503，无法使用 | `my-secret-pass` |
| `AUTH_SECRET` | 可选 | 生效 | 登录 token 的 HMAC 密钥。不设置则进程内随机：**每次重启后所有人需重新登录**。多实例部署或希望重启不掉登录态时固定它 | `a-long-random-string` |
| `DATA_DIR` | 可选 | 生效 | 数据目录（作品/角色卡/世界书/密钥等全部落盘于此）。Docker/Zeabur 内固定 `/app/data` 并挂卷；本地默认 `v3/data` | `/app/data` |
| `PORT` | 可选 | 生效 | 监听端口。Docker/Zeabur 内固定 3001 | `3001` |
| `LOG_DIR` | 可选 | 生效 | 日志目录。Docker/Zeabur 内固定 `/app/logs`；本地默认 `v3/logs` | `/app/logs` |
| `LOG_LEVEL` | 可选 | 生效 | 日志级别（pino）：`info`（默认）/ `debug` / `error` | `info` |
| `OPENAI_API_KEY` + `OPENAI_BASE_URL` | 可选 | **预留** | 当前版本**不支持从环境变量读取**。登录后在 `/settings` 录入（OpenAI 兼容通道可自定义 baseUrl 接中转站），落盘 `data/secrets.json` | — |
| `GEMINI_API_KEY` | 可选 | **预留** | 同上：`/settings` 录入，env 预读未实现 | — |
| `ANTHROPIC_API_KEY` | 可选 | **预留** | 同上：`/settings` 录入（通道名 claude），env 预读未实现 | — |
| `TTS_BASE_URL` | 可选 | **预留** | 当前版本**不支持从环境变量读取**。登录后在 `/settings` 填 TTS 服务地址，落盘 `data/config.json` 的 `ttsBaseUrl` | — |

### 密钥与 TTS 的正确配置方式（主路径）

密钥不进环境变量，**登录后在 `/settings` 页面录入**，由服务端明文落盘到数据卷（仅服务端可读，任何接口不回传明文，只回布尔掩码）：

| 内容 | 录入位置 | 落盘文件 | 健康检查反馈 |
|---|---|---|---|
| LLM 密钥（openai / gemini / claude 三通道） | `/settings` 密钥面板 | `data/secrets.json` | `/api/health` 的 `llm` 对应通道变 `true` |
| TTS 地址（easyvoice 服务，含 `/api/v1/tts` 路径） | `/settings` | `data/config.json` 的 `ttsBaseUrl` | `/api/health` 的 `tts` 由 `unset` 变 `ok` |

以上数据都在 `DATA_DIR` 下，随 volume 持久化——**录入一次，重启/更新不丢**。

## 2. Zeabur 部署步骤

前置：GitHub 仓库已包含 `v3/`（含 `Dockerfile`、`zeabur.yml`）；easyvoice 服务已在同一 Zeabur 账号下运行。

1. **新建项目**：Zeabur 控制台 → New Project（选区域）。
2. **添加 Git 服务**：Add Service → Git → 选择本仓库。在服务设置的 **Root Directory** 填 `v3`。
3. **确认构建方式**：目录内存在 `Dockerfile`，Zeabur 走 Docker 构建（多阶段：builder 全量构建 → prod-deps 生产依赖 → runner 精简运行层）。构建日志可见三个阶段依次完成，最终 `CMD ["node","--import","tsx","src/main.ts"]`。
4. **配 Volume**（服务 → Volumes）：挂载两卷——
   - `/app/data`（**必配**：数据持久化，不挂则重启丢全部作品与密钥）
   - `/app/logs`（可选：日志落盘）
5. **配环境变量**（服务 → Environment）：至少 `ACCESS_PASSWORD=你的密码`；建议加 `AUTH_SECRET=<长随机串>`（防重启掉登录态）。
6. **配网络**（服务 → Networking）：暴露端口 `3001`（HTTP），绑定/生成域名。
7. **部署完成后自检**：浏览器打开域名应看到登录页；再核对健康检查（见 §4）。
8. **录入密钥与 TTS**：用 `ACCESS_PASSWORD` 登录 → `/settings` → 录入 LLM 密钥、TTS 地址。

### easyvoice 对接

TTS 走既有 easyvoice Zeabur 服务，无需重复部署。在 `/settings` 把 TTS 地址填成 easyvoice 的**公网完整地址**（含 API 路径），例如：

```
https://<你的easyvoice域名>.zeabur.app/api/v1/tts
```

填完回首页看 `/api/health`：`tts` 应变 `ok`（探针 3 秒超时内收到任何 HTTP 响应即算可达）。`down` 则检查地址拼写与服务是否在线。

## 3. 健康检查 `/api/health` 解读

免鉴权，部署后先看它。返回体三段：

```json
{ "storage": "ok", "tts": "unset", "llm": { "openai": false, "gemini": false, "claude": false } }
```

| 字段 | 取值 | 含义 | 处置 |
|---|---|---|---|
| `storage` | `ok` / `fail` | data 目录写入探针（写探针文件再删除） | `fail` = volume 未挂载或无写权限，**必须修复**，否则数据不落盘 |
| `tts` | `unset` / `ok` / `down` | `unset`=未配置 TTS 地址；`ok`=3s 内收到响应；`down`=网络层失败 | 未配置属正常；`down` 查 TTS 地址与 easyvoice 服务状态 |
| `llm` | 三通道布尔掩码 | `true`=该通道密钥已录入 | 全 `false` 是新部署的预期态；用到哪个通道录哪个 |

**全新部署的合格线**：`storage: "ok"`，`tts: "unset"`，`llm` 全 `false`——这三项即「环境可用」，其余属配置项未录入。

## 4. 本地 Docker 验证

在 `v3/` 目录下（Windows Git Bash）：

```bash
# 1. 构建（首次约 2-5 分钟，依赖有层缓存）
docker build -t novel-workshop-v3 .

# 2. 启动（3011 宿主端口 → 容器 3001；临时命名卷持久化数据）
docker run -d --name novel-v3-test -p 3011:3001 \
  -e ACCESS_PASSWORD=dockertest \
  -v novel-v3-data:/app/data \
  novel-workshop-v3

# 3. 健康检查：期望 {"storage":"ok","tts":"unset","llm":{"openai":false,"gemini":false,"claude":false}}
curl http://localhost:3011/api/health

# 4. 登录接口：期望 {"ok":true} 并种下 token cookie
curl -i -X POST http://localhost:3011/api/auth/login \
  -H "Content-Type: application/json" -d '{"password":"dockertest"}'

# 5. 静态页：期望 200（HTML）
curl -I http://localhost:3011/

# 清理
docker rm -f novel-v3-test
docker volume rm novel-v3-data   # 不要数据就删卷
```

## 5. 备份与恢复

所有业务数据集中在 `DATA_DIR`（本地 `v3/data`，容器/Zeabur 为 `/app/data`）：

```
data/
├─ secrets.json          # LLM 密钥（敏感，勿外传）
├─ config.json           # TTS 地址 + 全局变量
├─ characters/           # 角色卡
├─ worldbooks/           # 世界书
├─ presets/              # 预设
├─ regex-scripts/        # 正则脚本
├─ works/<workId>/       # 作品（work.json 元数据 + messages.jsonl 消息流）
└─ backups/              # 备份产物默认落这里
```

**备份**（本地 / 能进 shell 的环境，在 `v3/` 下执行）：

```bash
bash scripts/backup.sh
# → 生成 backups/backup-<时间戳>.tar.gz（打包整个 data/）
```

**恢复**：在 `v3/` 根目录解包覆盖（解包后 `data/` 整体被还原）：

```bash
tar -xzf backups/backup-<时间戳>.tar.gz
```

**Zeabur 上的备份**：Volumes 面板可下载卷内容；或本地拉取镜像后把 volume 数据拷出（`docker run --rm -v novel-v3-data:/data alpine tar cz -C /data . > backup.tar.gz`）。建议定期备份并异地保存一份。

## 6. 常见问题（健康检查红项排查）

| 现象 | 原因 | 处置 |
|---|---|---|
| 登录接口 503「服务端未配置 ACCESS_PASSWORD」 | 环境变量没配或没生效 | 服务 → Environment 加 `ACCESS_PASSWORD` 后重启部署 |
| `/api/health` 的 `storage: "fail"` | Volume 未挂载 `/app/data`，或权限不足 | 检查服务 Volumes 配置；确认挂载路径精确为 `/app/data` |
| `tts: "down"` | TTS 地址填错 / easyvoice 服务没在线 / 网络策略拦截 | 核对 `/settings` 里地址是否含 `/api/v1/tts`；单独浏览器访问该地址确认可达 |
| `tts: "unset"` 且 `/settings` 已填 | 配置未保存成功 | 看 `/settings` 保存提示；确认 `config.json` 出现在数据卷 |
| 某通道 `llm: false` 但已录入 | 密钥面板保存失败（如 apiKey 为空） | 重录；`GET /api/secrets` 只回掩码，录成功即 true |
| 重启后全员掉登录 | 未设 `AUTH_SECRET`，token 密钥随机 | 加 `AUTH_SECRET` 环境变量并保持不变 |
| 首页白屏 / 静态资源 404 | 镜像内 `server/public` 为空（构建阶段失败） | 查 Zeabur 构建日志的 builder 阶段；本地 `bash scripts/build.sh` 复现 |
| 写作中 LLM 无响应 | 通道密钥未录 / 上游不通 | `/settings` 确认通道掩码为 true；`/api/health` 看不到通道连通性，属正常（密钥掩码≠连通探针） |

## 本地 Docker 演练（上线前测试）

上线前用与生产同构的镜像做一次完整演练（构建 → 起服务 → 生成链路 → 重启持久化）：

```bash
bash scripts/rehearsal.sh        # 全流程：构建 → 起服务 → 冒烟 → 重启验证持久化
bash scripts/rehearsal.sh down   # 停止（数据卷保留）
bash scripts/rehearsal.sh clean  # 停止并清空数据卷（彻底重置）
```

- 入口 `http://localhost:3011`，密码 `ACCESS_PASSWORD`（默认 `rehearsal123`）
- 自带 mock LLM 上游（`:3100`，OpenAI 兼容假流式）——**无需真实密钥**即可走通
  「建作品 → 生成（SSE）→ 标题解析 → 幂等入库」全链路；冒烟脚本自动把 openai 通道
  指向 mock 并做生成 + 入库 + 重启持久化断言
- 数据卷 `rehearsal-data` 持久化 `/app/data`（作品/资产/secrets）；真实通道演练时在
  `/settings` 录入真实密钥即可，mock 服务空转不影响
- 两阶段冒烟细节见 `scripts/rehearsal-smoke.mjs`（phase1 首次全链路 / phase2 重启持久化）
