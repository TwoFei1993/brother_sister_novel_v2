## 二、缺陷清单

### 已当场修复（2 项）

**D1（中）· 生成入库后本地 revision 失同步，后续 PATCH 全部 409 回滚**
- 现象：生成/换一支/连写完成后，「变量持久化失败（不影响正文入库）」警告 + 视图切换「视图偏好持久化失败，已回滚」。每次 upsert 消息服务端 revision+1 并随响应返回，但前端 `upsertMessage` 忽略该字段，本地 store revision 停留在页面加载值，后续所有带乐观锁的 PATCH（变量回写、视图偏好、设置保存）持续 409。
- 修复：`client/src/api/works.ts` upsertMessage 返回 `{ok, revision}`；`client/src/hooks/generation-pipeline.ts` persistMessage 将最新 revision 同步回 work store（novel/chat 两条链路同时覆盖）。相关 60 个单测全绿，UI 复测视图切换无 409。

**D3（小）· 文风面板「保存画像/清除文风」误清未保存的分析预览**
- 现象：saveGuide 成功后无条件 `setProfile('')`，用户点「保存画像」（保存当前 guide）会把尚未保存的「文风画像（可修改）」分析草稿清掉，无法找回。
- 修复：`StyleClonePanel.tsx` 仅当保存的值就是 profile 本身时才收起草稿。

### 记录待修（3 项）

**D2（小）· 无**——已并入 D1/D3 说明（验证过程中 PATCH 200 但 styleGuide 为空系点错按钮「保存画像」而非「保存到作品」，两个保存按钮并存略易混淆，可考虑合并入口）。

**D4（中，架构级）· claude 通道思考流（thinking_delta）被丢弃，💭折叠真实链路失效**
- `server/src/services/upstream.ts` extractStreamDelta 的 claude 分支仅处理 `content_block_delta && delta.type==='text_delta'`；MiniMax-M3 等思考模型的思考内容走 `thinking_delta`，被静默丢弃。后果：思考 token 照常计费（单章 tokenCount 28,672 含思考）但用户不可见，`extra.rawThinking` 恒空，反馈⑨的折叠展示在真实思考模型下无法触发（UI 功能本身正常，单测覆盖）。
- 修复建议：upstream 收集 thinking_delta → SSE 帧增加 thinking 字段（`data:{"text":"","thinking":"…"}`）→ 前端生成流拼接后入 extra.rawThinking。涉及 shared 帧协议 + server 转发 + 前端管道三层，建议单独任务处理。

**D5（小）· 登出功能未实现**
- 前端无登出入口，后端无 `/api/auth/logout`。会话只能等 cookie 7 天自然过期（或手清浏览器数据）。单用户本地工具影响有限，建议补一个「清除 cookie + 跳登录页」的入口。

### 验证过程观察（非缺陷）

- 连写每轮 3 章后自动停是设计行为（BATCH_CHUNK_SIZE，控长上下文质量退化），非 bug；「停止」为软停止：当前章写完入库后中断，不产生半章。
- 标题解析兜底：模型未按 `# 第N章` 输出标题行时，回退为「第N章 + 指令摘要」。
- mock 固定文本导致两个候选内容相同，属 mock 行为非候选机制问题。

## 三、真实生成 token 消耗（通道 claude / MiniMax-M3）

| 用例 | tokenCount（prompt+输出） | 备注 |
|------|---------------------------|------|
| novel 首章（通道误用真实，见下） | 8,508 | 意图走 mock，但前端 llmPrefs 默认 claude，实际真实生成 |
| chat 双卡 3 轮（含提及检测） | ≈ 12,000（估算） | 短档回复 ~350 字/轮 |
| 向导 AI 解析（16,381 字 docx） | ≈ 18,000（估算） | 页面提示约 16k token |
| 📖按大纲 第 1 章 | 28,672 | 含思考 token 与 8 卡+世界书 prompt |
| 📖按大纲 第 2 章（完整） | ≈ 25,000（估算） | 与第 1 章规模相近 |
| 📖按大纲 第 2 章（首次被停止，流式已完成大半） | ≈ 20,000（估算） | 停止不回收已产生 token |
| 文风分析 ×2 | ≈ 3,000 | |
| **合计** | **≈ 115,000（估算）** | **超出 8 万预算** |

超预算原因：① 前端 llmPrefs 默认 `claude/MiniMax-M3`，域三第 6 项在确认 mock 配置前误用真实通道生成了一章；② 📖按大纲生成跑了两次全量（第一次 2 章处停止，但流式消耗不回收）；③ MiniMax-M3 思考 token 占比高（见 D4，思考不可见但计费）。后续验证建议：涉及生成的用例先显式确认/切换通道，再执行。
