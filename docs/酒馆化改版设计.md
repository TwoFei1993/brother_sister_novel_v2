# 兄妹小说工坊 V3：酒馆化全面改版设计文档

> 状态：已定稿（2026-10-19 与用户逐节确认）
> 范围：前端 + 后端全面改版，借鉴 SillyTavern（酒馆）核心架构
> 参考源码：`酒馆代码/SillyTavern`（不修改，仅作概念参考）

---

## 1. 背景与目标

现有"异界兄妹"是 Lovable 生成的纯前端小说生成站：数据全存 localStorage（20 本上限）、LLM 层只有一个写死的 OpenAI 兼容调用函数、上下文 = 全量大纲 + 每章前 300 字摘要、无角色/记忆/分支概念。

改版目标：以酒馆的成熟机制（角色卡、世界书、预设、正则、swipe、深度注入、token 预算）重建生成引擎，同时保留现有打磨过的体验资产（TTS 听书、题材主题、移动端 PWA）。

**成功判据**：导入酒馆社区人物卡/世界书/预设即可开写；互动小说与对话写作双模式可用；生成质量由世界书按需注入 + 滚动摘要支撑；部署到 Zeabur 后 `/api/health` 全绿。

│     └─ storage/         # 文件读写（原子写、备份）

### 3.2 核心数据流

提示词组装在**前端**（实时 token 预览、可视化编排），后端是薄代理：

1. 前端引擎产出 `messages[]` + `source(openai|gemini|claude)` + 采样参数
2. `POST /api/llm/generate`（SSE 流式）
3. 后端按 source 转换消息格式（仿酒馆 `prompt-converters`）、注入密钥、请求上游
4. SSE 管道回传，前端逐 chunk 渲染 + 正则清洗 + 入库

### 3.3 部署保障（用户重点关注）

- **唯一部署路径**：Zeabur 两个服务——主服务（Express 托管 client 构建产物）+ 现有 easyvoice。固定域名，废弃 cpolar。
- **同源策略**：前端 API 全走相对路径 `/api/*`；TTS 地址存服务端配置，前端启动从 `/api/config` 拉取。前端代码**零硬编码后端地址**。
- **配置清单**：`ACCESS_PASSWORD` / `OPENAI_API_KEY(+BASE_URL)` / `GEMINI_API_KEY` / `ANTHROPIC_API_KEY` / `TTS_BASE_URL` / `DATA_DIR`，写进 `docs/部署指南.md`。
- **可验证**：`/api/health` 自检（数据目录可写、TTS 连通、各 LLM 通道连通）；`scripts/dev.sh` 一键本地起全栈；`Dockerfile` 兜底不锁死 Zeabur。
- **数据安全**：`data/` 挂 Zeabur volume；`scripts/backup.sh` 打包导出。
- **交付标准**：实施完成后本地 `scripts/dev.sh` 真实跑通全流程（建卡→双模式写作→TTS→导入酒馆资产）才视为完成。

## 4. 数据模型与存储

### 4.1 服务端存储布局

```
data/
├─ secrets.json          # LLM 密钥（仅服务端可读）
├─ config.json           # TTS 地址等非敏感配置 + 全局变量
├─ characters/<id>.json  # 角色卡（内部 JSON 格式）
├─ worldbooks/<id>.json  # 世界书（酒馆原生格式）
├─ presets/<id>.json     # 预设（酒馆原生格式）
├─ regex-scripts/<id>.json
├─ works/<workId>/
│  ├─ work.json          # 作品元数据 + 绑定 + 设定 + voiceMap
│  └─ messages.jsonl     # 消息流（一行一条）
└─ backups/
```

### 4.2 统一消息模型（shared/types）

```ts
interface Message {
  id: string;
  role: 'user' | 'assistant';
  name: string;                  // "作者" / "小说家" / 角色名
  content: string;
  createdAt: number;
  swipes: string[];              // 消息级分支候选
  swipeId: number;
  chapter?: { index: number; title: string };  // novel 模式：此消息=一章
  directive?: string;            // novel 模式：生成本章时的剧情指令
  extra: {
    model?: string;
    tokenCount?: number;
    generationMs?: number;
    statusSnapshot?: Record<string, string | number>;  // COT 状态快照
    activatedEntries?: string[];                       // 本次激活的世界书条目审计
  };
}
```

### 4.3 双模式（Work.mode）

```ts
interface Work {
  id: string;
  title: string;
  mode: 'novel' | 'chat';        // 同一数据结构，语义不同
  genre: string;                 // 题材主题（6 套 + custom）
  characterIds: string[];        // 多角色卡（哥哥/妹妹/配角）
  worldbookIds: string[];        // 多世界书
  presetId: string;
  regexScriptIds: string[];
  settings: NovelSettings;       // 沿用现有细纲/文风等字段
  voiceMap: Record<string, string>;  // 角色名 → TTS 声音
  viewPreference?: 'a' | 'b' | 'c';
  createdAt: number; updatedAt: number;
}
```

- **novel**：用户消息=作者指令（不进正文）；AI 消息带 `chapter` 元数据；A/B/C 三视图呈现；多角色卡字段合并注入（AI=小说家视角）
- **chat**：用户消息=对话内容；AI 扮演角色（单角色主聊或多角色轮换，酒馆群聊式）；默认 A 视图形态

### 4.4 兼容性与迁移

- `worldbooks/`、`presets/`、`regex-scripts/` 存酒馆原生 JSON（字段一一对应）
- 角色卡内部 JSON，导入导出时转换 PNG V2/V3（tEXt chunk `chara`/`ccv3` base64，复用酒馆方案）
- 旧站迁移：设置页提供入口，上传旧 `novel_history` 导出 JSON → 转换为 Work（旧 chapters → 带 chapter 元数据的消息流）

## 5. 提示词引擎（client/src/engine/，纯函数）

### 5.1 流水线

```
① 原料：预设 prompts[] · 角色卡×N · 世界书条目 · NovelSettings · 滚动摘要 · 消息流 · 作者注释 · 当前指令
② 世界书扫描 worldbook.ts：
   扫描最近 N 条消息（深度可配）→ 关键词/正则键匹配 → 二级键逻辑
   (AND_ANY/NOT_ALL/NOT_ANY/AND_ALL) → 常驻条目直通 → 概率 roll
   → 递归扫描（命中内容再触发，限步数）→ 激活条目集（记录进 extra.activatedEntries）
③ 宏替换 macros.ts：{{user}} {{char}} {{original}} · 变量 {{getvar::}}/{{setvar::}}
   （作用域：作品级存 work.json，全局存 config.json）
④ 装配+预算 assemble.ts + budget.ts：按预设 prompt_order 装填 marker：
   main → 世界书(前) → 角色描述 → 设定 → 世界书(后) → 摘要
   → 聊天历史（从新到旧，token 装不下即截断）→ 深度注入 → jailbreak → 当前指令
   总预算 = max_context − max_tokens
⑤ 发送：POST /api/llm/generate（SSE）
⑥ 后处理 regex.ts：正则双轨（promptOnly 进提示词清洗 / markdownOnly 仅显示美化）
   状态栏块解析 → statusSnapshot
```

### 5.2 世界书引擎兼容分级

**一期完整支持**：关键词键（含正则键）、二级键四逻辑、常驻条目、扫描深度、递归扫描、概率、order 排序、插入位置（前/后/深度+角色）、大小写、全词匹配、条目级覆盖全局设置。

**一期存而不用**（导入不丢失、引擎忽略、文档标注支持矩阵）：定时效果（sticky/cooldown/delay）、互斥组、outlet、automationId、角色过滤、向量化、ANTop/ANBottom/EM 位置（映射到近似位置）。

### 5.3 记忆系统

- 滚动摘要：每 N 章（默认 5）自动摘要前文，注入固定位置（摘要 prompt 可配）
- 最近 K 章全文进聊天历史，token 预算裁剪
- COT 状态栏：常驻世界书条目要求 AI 每章末输出状态块 → promptOnly 正则剥离显示、引擎解析存 statusSnapshot → 工作台视图渲染变量面板 → 世界书可按变量触发不同条目

### 5.4 Token 计数双轨

前端近似估算法（中文字符加权）做实时预算与 UI；`/api/tokenize` 精确端点发送前校验，超预算自动多截。

## 6. 后端 API（server/src/routes/）

| 路由 | 功能 |
|---|---|
| `POST /api/auth/login` `GET /api/auth/check` | 单密码登录/token 校验 |

| `CRUD /api/presets` + import/export | 预设（酒馆格式） |
| `CRUD /api/regex-scripts` | 正则脚本 |
| `GET/POST/PATCH /api/works` | 作品 CRUD |
| `GET/POST/PATCH/DELETE /api/works/:id/messages` | 消息流（追加/更新 swipe/删除） |
| `POST /api/llm/generate` | LLM 代理（source 分发 + 协议转换 + SSE） |
| `POST /api/llm/test` | 连通性测试 |

## 7. 前端架构

### 7.1 路由与视图

- `/` 书架：作品网格（搜索/排序/改名/删除，沿用现有交互）+ 新建（选模式/题材/绑定卡与书）
- `/work/:id` 写作台：
  - novel：A 对话流（气泡流+swipe 箭头+指令重放）/ B 沉漫阅读（连续滚动+底部指挥条：指令输入·续写·换一支）/ C 工作台（侧栏：状态变量+世界书激活灯+指令历史+快速指令；主区阅读流）。移动端默认 B，C 侧栏收抽屉
  - chat：酒馆式对话（单/多角色），swipe/重roll/编辑
- `/library` 资源库：四类资产管理 + 资源中心（精选索引搜索 + URL 导入 + 本地上传）
- `/settings`：LLM 三通道（密钥存服务端）/ TTS / 界面 / 旧数据迁移
- `/login` 单密码

### 7.2 状态管理

Zustand 五域 store：`workStore`（当前作品+消息流）、`generationStore`（生成中状态/流式缓冲/停止）、`libraryStore`、`settingsStore`、`ttsStore`。持久化全在服务端，store 为会话缓存，乐观更新+失败回滚。

### 7.3 保留移植资产

- 题材主题：6 套 CSS 变量体系（data-theme），作品卡绑定
- TTS：easyvoice 段落预取算法、自动连播、语速；升级 voiceMap 角色分声（段落说话人路由：引号归属/角色名前缀）
- PWA：manifest/safe-area/触控优化/离线壳
- 粘贴大纲自动填充 → 改造为"从大纲生成角色卡+世界书"向导
- 节日彩蛋、书名智能提取、TXT 导出

## 8. 资源中心

- 精选索引 `resources/index.json`：四类资源条目（名称/描述/标签/来源/下载 URL），实施时调研收录公开知名资源（ny 预设等），持续可补
- 站内搜索 + 标签筛选 + 一键导入
- URL 直链导入：服务端拉取 → 酒馆格式校验 → 字段映射入库，失败给明确错误
- 本地文件上传导入（同格式校验管道）

## 9. 错误处理

- LLM 上游错误翻译分类（密钥无效/额度耗尽/超时/内容被拒/网络）；网络类自动重试（指数退避 ≤2 次），4xx 不重试
- 流中断保留半成品，可"继续"续写；停止按钮即 AbortController
- 服务端文件原子写（tmp+rename）；JSONL 完整性校验
- 前端乐观更新回滚 + toast；断网提示
- 服务端结构化日志落 `logs/`（按天滚动）

## 10. 测试策略

- **引擎单测（重点）**：世界书扫描（关键词/二级键/递归/概率/预算）、token 装填、宏替换、正则双轨
- **兼容性回归**：真实酒馆样本 fixtures 导入→导出 roundtrip 字段不丢失
- **API 集成**：supertest 全路由
- **E2E 冒烟**：Playwright 核心路径（登录→建作品→写一章→swipe→TTS）
- 用户要求的 **50+ 测试用例** 在此框架下产出（引擎单测为主力）
