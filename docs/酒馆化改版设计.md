# 兄妹小说工坊 V3：酒馆化全面改版设计文档

> 状态：已定稿（2026-10-19 与用户逐节确认；同日经规格评审 14 项问题修复后复审定稿）
> 范围：前端 + 后端全面改版，借鉴 SillyTavern（酒馆）核心架构
> 参考源码：`酒馆代码/SillyTavern`（不修改，仅作概念参考）

---

## 1. 背景与目标

现有"异界兄妹"是 Lovable 生成的纯前端小说生成站：数据全存 localStorage（20 本上限）、LLM 层只有一个写死的 OpenAI 兼容调用函数、上下文 = 全量大纲 + 每章前 300 字摘要、无角色/记忆/分支概念。

改版目标：以酒馆的成熟机制（角色卡、世界书、预设、正则、swipe、深度注入、token 预算）重建生成引擎，同时保留现有打磨过的体验资产（TTS 听书、题材主题、移动端 PWA）。

**成功判据**：导入酒馆社区人物卡/世界书/预设即可开写；互动小说与对话写作双模式可用；生成质量由世界书按需注入 + 滚动摘要支撑；部署到 Zeabur 后 `/api/health` 全绿。

### 3.2 核心数据流

提示词组装在**前端**（实时 token 预览、可视化编排），后端是薄代理：

1. 前端引擎产出 `messages[]` + `source(openai|gemini|claude)` + 采样参数
2. `POST /api/llm/generate`（SSE 流式，无状态——生成与入库解耦，见 §9.2）
3. 后端按 source 转换消息格式（仿酒馆 `prompt-converters`）、注入密钥、请求上游
4. SSE 管道回传，前端逐 chunk 渲染 + 正则清洗；**完成时**由前端带 `messageId` 幂等入库（服务端 upsert）

### 3.3 部署保障（用户重点关注）

- **唯一部署路径**：Zeabur 两个服务——主服务（Express 托管 client 构建产物）+ 现有 easyvoice。固定域名，废弃 cpolar。
- **同源策略**：前端 API 全走相对路径 `/api/*`；TTS 地址存服务端配置，**登录成功后**前端从 `/api/config` 拉取（未登录仅需 `/api/auth/check`，不存在时序矛盾）。前端代码**零硬编码后端地址**。
- **配置清单**：`ACCESS_PASSWORD` / `OPENAI_API_KEY(+BASE_URL)` / `GEMINI_API_KEY` / `ANTHROPIC_API_KEY` / `TTS_BASE_URL` / `DATA_DIR`，写进 `docs/部署指南.md`。
- **可验证**：`/api/health` 自检（数据目录可写、TTS 连通、各 LLM 通道连通）；`scripts/dev.sh` 一键本地起全栈；`Dockerfile` 兜底不锁死 Zeabur。
- **数据安全**：`data/` 挂 Zeabur volume；`scripts/backup.sh` 打包导出。
- **交付标准**：实施完成后本地 `scripts/dev.sh` 真实跑通全流程（建卡→双模式写作→TTS→导入酒馆资产）才视为完成。

## 4. 数据模型与存储

### 4.1 服务端存储布局

```
data/
├─ secrets.json          # LLM 密钥（仅服务端可读）
├─ config.json           # TTS 地址等非敏感配置 + 全局变量
├─ characters/<id>.json  # 角色卡（内部 JSON 格式）
├─ worldbooks/<id>.json  # 世界书（酒馆原生格式）
├─ presets/<id>.json     # 预设（酒馆原生格式）
├─ regex-scripts/<id>.json
├─ works/<workId>/
│  ├─ work.json          # 作品元数据 + 绑定 + 设定 + voiceMap + revision 版本号
│  └─ messages.jsonl     # 消息流（一行一条）
└─ backups/
```

### 4.2 统一消息模型（shared/types）

```ts
interface Message {
  id: string;                    // 前端生成（uuid），入库幂等键
  role: 'user' | 'assistant';
  name: string;                  // "作者" / "小说家" / 角色名（chat 模式=激活角色）
  content: string;
  createdAt: number;
  swipes: string[];              // 消息级分支候选（上限可配，默认 20，超出提示清理）
  swipeId: number;
  chapter?: { index: number; title: string };  // novel 模式：此消息=一章
  directive?: string;            // novel 模式：生成本章时的剧情指令
  extra: {
    model?: string;
    tokenCount?: number;
    generationMs?: number;
    statusSnapshot?: Record<string, string | number>;  // COT 状态快照
    activatedEntries?: string[];                       // 本次激活的世界书条目审计
  };
}
```

**章节标题来源**：约定 AI 输出首行为 `# 第N章 标题`（复用现有站正则资产），引擎后处理剥离并存入 `chapter.title`；无首行标记时兜底取指令首句（≤20 字）或"第N章"。

### 4.3 双模式（Work.mode）

```ts
interface Work {
  id: string;
  revision: number;              // 乐观版本号，每次写入 +1
  title: string;
  mode: 'novel' | 'chat';        // 同一数据结构，语义不同
  genre: string;                 // 题材主题（6 套 + custom）
  characterIds: string[];        // 多角色卡（哥哥/妹妹/配角）
  worldbookIds: string[];        // 多世界书
  presetId: string;
  regexScriptIds: string[];
  settings: NovelSettings;       // 沿用现有细纲/文风等字段
  voiceMap: Record<string, string>;  // 角色名 → TTS 声音
  viewPreference?: 'a' | 'b' | 'c';
  createdAt: number; updatedAt: number;
}
```

- **novel**：用户消息=作者指令（不进正文）；AI 消息带 `chapter` 元数据；A/B/C 三视图呈现；多角色卡字段合并注入（AI=小说家视角）
- **chat**：用户消息=对话内容；AI 扮演角色；**多角色激活策略**（M3 交付）：
  - 激活顺序 = 提及检测（用户消息中出现角色名/@名字 优先）→ 无提及时按成员列表自然轮换 → 用户可手动指定下一个发言者（UI 点选）
  - AI 消息 `name` = 本次激活角色；`{{char}}` 宏绑定当前激活角色；voiceMap 按 `name` 路由 TTS
  - 验收场景：3 角色卡（哥哥/妹妹/配角），用户消息提及"妹妹"→ 本次生成 name=妹妹；无提及 → 轮换到列表下一位

### 4.4 角色卡字段与预设的覆盖关系（对齐酒馆行为）

- 作品设置含开关 **「允许角色卡覆盖预设」默认开**（与酒馆一致）：
  - 卡 `system_prompt` 非空 → **替换**预设 `main` 提示词内容；**多卡时按 characterIds 顺序取首张非空者**，并记录进装配审计（extra.activatedEntries 同级）
  - 卡 `post_history_instructions` 非空 → **替换**预设 `jailbreak` 提示词；多卡取首张非空者
  - 卡 `alternate_greetings` → 开新作品时可选备选开场
- 开关关闭 → 预设原样使用，卡字段仅存不用
- `depth_prompt`（卡的深度提示）→ 走深度注入通道，角色默认值 depth=4

### 4.5 并发与一致性控制

单密码系统天然多设备并发（手机+电脑），采用**双层防护**：

1. **per-work 内存互斥写队列**（server `middleware/writer.ts`）：同一 `workId` 的写操作（PATCH work.json、追加/改写 messages.jsonl）串行排队执行；不同 work 并行。队列实现为 `Map<workId, Promise chain>`。
2. **乐观版本号**：`work.json` 带 `revision`；客户端 PATCH 须携带所读 `revision`，服务端不匹配则 409，客户端刷新重放（消息追加用 messageId 幂等 upsert，不受 revision 限制）。
3. **JSONL 写策略**：追加=行级 append（持锁）；编辑/删除中间消息=整文件重写（tmp+rename 原子替换，持锁）；单条消息的编辑/删除并发语义为 **last-write-wins**（后写覆盖，简化单用户场景）。

### 4.6 messages.jsonl 读取策略（大文件）

- 打开作品：`GET /api/works/:id/messages?tail=50` 只读**尾部 50 条**
- 向上翻load更早章节：`?before=<messageId>&limit=50` 游标分页
- 多端增量拉新：`?since=<messageId>` 返回该消息之后的新消息（轮询同步用）
- B 视图连续滚动 = 前端按需向上拉取分页；书架字数统计读取 work.json 缓存的计数（写入时维护），不扫全文件

### 4.7 兼容性与迁移

- `worldbooks/`、`presets/`、`regex-scripts/` 存酒馆原生 JSON（字段一一对应）
- 角色卡内部 JSON，导入导出时转换 PNG V2/V3（tEXt chunk `chara`/`ccv3` base64，复用酒馆方案）
- **prompt_order 的 character_id 映射**：导入酒馆预设时取 `character_id === 100001`（chat completion dummy）的排序列表，忽略其余条目
- 旧站迁移：设置页提供入口，上传旧 `novel_history` 导出 JSON → 转换为 Work（旧 chapters → 带 chapter 元数据的消息流）

## 5. 提示词引擎（client/src/engine/，纯函数）

### 5.1 流水线

```
① 原料：预设 prompts[] · 角色卡×N（含 §4.4 覆盖规则） · 世界书条目 · NovelSettings
        · 滚动摘要 · 消息流 · 作者注释 · 当前指令
② 世界书扫描 worldbook.ts：
   扫描最近 N 条消息（深度可配）→ 关键词/正则键匹配 → 二级键逻辑
   (AND_ANY/NOT_ALL/NOT_ANY/AND_ALL) → 常驻条目直通 → 概率 roll
   → 递归扫描（命中内容再触发，限步数）→ 激活条目集（记录进 extra.activatedEntries）
③ 宏替换 macros.ts：{{user}} {{char}} {{original}} · 变量 {{getvar::}}/{{setvar::}}
   （作用域：作品级存 work.json，全局存 config.json；chat 多角色时 {{char}}=当前激活角色）
④ 装配+预算 assemble.ts + budget.ts：按预设 prompt_order 装填 marker：
   main → 世界书(前) → 角色描述 → 设定 → 世界书(后) → 摘要
   → 聊天历史（从新到旧装填，token 装不下即截断最旧；
     深度注入项[状态/COT/作者注释/卡depth_prompt]插入历史序列倒数第 depth 条位置，
     同 depth 按 order 降序、role system→user→assistant 排列——酒馆语义，非固定尾部）
   → jailbreak → 当前指令
   总预算 = max_context − max_tokens
⑤ 发送：POST /api/llm/generate（SSE）
⑥ 后处理 regex.ts：正则双轨（promptOnly 进提示词清洗 / markdownOnly 仅显示美化）
   首行标题剥离 → chapter.title；状态栏块解析 → statusSnapshot
```

### 5.2 世界书引擎兼容分级

**一期完整支持**：关键词键（含正则键）、二级键四逻辑、常驻条目、扫描深度、递归扫描、概率、order 排序、插入位置（前/后/深度+角色）、大小写、全词匹配、条目级覆盖全局设置。

**一期存而不用**（导入不丢失、引擎忽略、文档标注支持矩阵）：定时效果（sticky/cooldown/delay）、互斥组、outlet、automationId、角色过滤、向量化、ANTop/ANBottom/EM 位置（映射到相近的前/后位置）。

### 5.3 记忆系统

- 滚动摘要：每 N 章（默认 5）自动摘要前文，注入固定位置（摘要 prompt 可配）
- 最近 K 章全文进聊天历史，token 预算裁剪
- COT 状态栏：常驻世界书条目要求 AI 每章末输出状态块 → promptOnly 正则剥离显示、引擎解析存 statusSnapshot → 工作台视图渲染变量面板 → 世界书可按变量触发不同条目

### 5.4 Token 计数双轨

- 前端近似估算法（中文字符加权 1.5/字，英文按词）做实时预算与 UI
- `POST /api/tokenize` 发送前校验：按 source 路由——openai→tiktoken（按模型选 o200k/cl100k）；gemini/claude→字符启发式（无可用本地精确 tokenizer 时回退估算并在响应标注 `approximate: true`）；超预算返回建议裁剪深度，前端自动多截一章

## 6. 后端 API（server/src/routes/ 分组）

| 路由 | 功能 |
|---|---|
| `POST /api/auth/login` `GET /api/auth/check` | 单密码登录/token 校验（免鉴权） |
| `GET /api/health` | 自检：存储可写、TTS 连通、LLM 通道连通（免鉴权） |
| `GET/PUT /api/config` | 运行配置（TTS 地址等）下发/更新（登录后拉取） |
| `GET/PUT /api/secrets` | 密钥写入（读只回掩码） |
| `CRUD /api/characters` + `POST /import` `POST /export` | 角色卡 + PNG V2/V3 转换 |
| `CRUD /api/worldbooks` `CRUD /api/presets` `CRUD /api/regex-scripts` | 三类资产（酒馆原生格式）+ 各自 import/export |
| `GET/POST/PATCH/DELETE /api/works` | 作品 CRUD（DELETE 级联删除 `works/<id>/` 整目录；PATCH 带 revision 乐观锁） |
| `GET /api/works/:id/messages?tail|before|since` `POST .../messages` `PATCH .../messages/:mid` `DELETE .../messages/:mid` | 消息流：尾部/游标分页读、按 messageId 幂等追加、单条更新（swipe 切换/编辑）、单条删除 |
| `POST /api/llm/generate` | LLM 代理（source 分发 + 协议转换 + SSE，无状态） |
| `POST /api/llm/test` | 连通性测试 |
| `POST /api/tokenize` | 精确 token 计数（按 source 路由，§5.4） |
| `POST /api/resources/fetch` | 资源中心：URL 直链拉取 + 格式校验导入 |

鉴权：登录后发 HttpOnly cookie token，除 auth/health 外全走鉴权中间件；上传/请求体 zod 校验。

## 7. 前端架构

### 7.1 路由与视图

- `/` 书架：作品网格（搜索/排序/改名/删除，沿用现有交互）+ 新建（选模式/题材/绑定卡与书）
- `/work/:id` 写作台：
  - novel：A 对话流（气泡流+swipe 箭头+指令重放）/ B 沉漫阅读（连续滚动+底部指挥条：指令输入·续写·换一支；向上滚动按需拉取更早章节分页）/ C 工作台（侧栏：状态变量+世界书激活灯+指令历史+快速指令；主区阅读流）。移动端默认 B，C 侧栏收抽屉
  - chat：酒馆式对话（单/多角色按 §4.3 激活策略），swipe/重roll/编辑/手动指定下一个发言者
- `/library` 资源库：四类资产管理 + 资源中心（精选索引搜索 + URL 导入 + 本地上传）
- `/settings`：LLM 三通道（密钥存服务端）/ TTS / 界面 / 旧数据迁移
- `/login` 单密码

### 7.2 状态管理

Zustand 五域 store：`workStore`（当前作品+消息流窗口）、`generationStore`（生成中状态/流式缓冲/停止）、`libraryStore`、`settingsStore`、`ttsStore`。持久化全在服务端，store 为会话缓存，乐观更新+失败回滚（409 时自动刷新重放）。

### 7.3 保留移植资产

- 题材主题：6 套 CSS 变量体系（data-theme），作品卡绑定
- TTS：easyvoice 段落预取算法、自动连播、语速；升级 voiceMap 角色分声（段落说话人路由：引号归属/角色名前缀）
- PWA：manifest/safe-area/触控优化/离线壳
- 粘贴大纲自动填充 → 改造为"从大纲生成角色卡+世界书"向导
- 节日彩蛋、书名智能提取、TXT 导出

## 8. 资源中心

- 精选索引 `resources/index.json`：四类资源条目（名称/描述/标签/来源/下载 URL），实施时调研收录公开知名资源（ny 预设等），持续可补
- 站内搜索 + 标签筛选 + 一键导入
- URL 直链导入：服务端拉取 → 酒馆格式校验 → 字段映射入库（预设按 §4.7 的 character_id 规则取 prompt_order），失败给明确错误
- 本地文件上传导入（同格式校验管道）

## 9. 错误处理与内容安全

### 9.1 错误处理

- LLM 上游错误翻译分类（密钥无效/额度耗尽/超时/内容被拒/网络）；网络类自动重试（指数退避 ≤2 次），4xx 不重试
- 前端乐观更新回滚 + toast；断网提示；409 冲突自动刷新重放（§4.5）
- 服务端文件原子写（tmp+rename）+ per-work 写队列（§4.5）；JSONL 完整性校验
- 服务端结构化日志落 `logs/`（按天滚动）

### 9.2 生成事务性（明确决策：半成品不入库）

- 生成中的流式内容**仅前端暂存**（generationStore），不写服务端——刷新/关页即弃
- 流中断：已生成部分保留在界面上，用户点「继续」= 以续写指令重新组装上下文再发起（不是续传）
- 生成完成：前端带 `messageId` 调 `POST .../messages` 幂等入库，失败可安全重试（upsert 不产生重复）
- 服务端 `/api/llm/generate` 无状态，无需生成会话暂存

### 9.3 内容安全（XSS 净化）

- AI 输出与用户内容的 markdown 渲染**统一经 DOMPurify** 净化后才进 DOM
- **markdownOnly 正则轨道的输出同样过净化器**（导入的第三方正则脚本是直接攻击面）
- markdown 渲染层禁用原始 HTML 直通（`rehype-sanitize` 策略）
