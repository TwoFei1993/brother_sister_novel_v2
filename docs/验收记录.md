### 本任务发现并修复的缺陷（均已回归验证）

1. **server 数据目录基准分裂（必修）**：`routes/core/paths.ts` 的 `new URL('../..', import.meta.url)` 实际解析到 `src/` 而非注释声称的 `server/`，导致 secrets.json/config.json 落 `server/data/`，与 library 资产、作品的 `v3/data/` 分裂——backup.sh（tar v3/data）会**漏备份密钥与配置**。修复：paths.ts 改 `'../../..'` 与 crud.ts 同基准；`works.ts` 的 worksDir 从相对 cwd（`'data'`，`pnpm --filter` 下 cwd=server/ 会写错目录）改为绝对基准并导出；`messages.ts` 删除第二份相对 cwd 解析、复用 worksDir。验证：修复后全部数据统一落 `v3/data/`，旧 `server/data/` 清除后功能完好。
2. **世界书扫描不含本轮输入**：`generation-pipeline.ts` 与 `chat-flow.ts` 的 scanWorldInfo chatTexts 只含历史消息 content——空历史首次生成时世界书永不触发，有历史时指令关键词也不触发，与酒馆「用户输入参与扫描」语义不符。修复：本轮 directive / userMessage 作为最新文本置于 chatTexts 首位。
3. **无预设时世界书内容被静默丢弃**：EMPTY_PRESET 空 prompt_order 使 worldInfoBefore/After 块无处装填（绑定世界书但不绑预设是合法组合）。修复：EMPTY_PRESET 改为标准酒馆 marker 骨架（main→worldInfoBefore→charDesc→charPersonality→scenario→worldInfoAfter→chatHistory→jailbreak），并收敛 chat/novel 两份重复定义为 generation-pipeline 单点导出。
4. **mock-llm 流式死锁（工具修复）**：原 `req.on('close')` 在 Node≥16 中请求流读完 body 即触发；本任务为 mock 增加请求捕获（消费 body）后必然掐死推送 timer，表现为上游 120s 超时 502。修复：改监听 `res.on('close')`（连接真断才停），并注释说明缘由。
