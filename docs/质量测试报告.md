## 二、测试环境与方法

- 后端：http://localhost:3001（dev123 登录，cookie 鉴权）
- 组装：直接调用 client engine 纯函数——`scanWorldInfo`（scanDepth 10、recursive、maxRecursionSteps 10，与 `generation-pipeline.ts` 的 SCAN_SETTINGS 同参）+ `assemblePrompt`（无预设时用 EMPTY_PRESET 八 marker 骨架；budgetTokens 60000；novel 走 directive「剧情指引：」通道 / chat 走 userMessage 通道；macroEnv：novel user=「作者」/ chat user=「用户」，char=主卡名）
- 生成：`POST /api/llm/generate`，`stream: true`，params `{max_tokens: 4096, temperature: 0.8}`，手写 SSE 帧解析（`data: {"text":…}` + `[DONE]`，错误帧即抛）
- 后处理：novel 走 `postprocessMessage`（全时轨正则 + 状态块 + 标题解析）；chat 走全时轨正则 + 状态块（跳过标题，对齐 `finalizeChatGeneration`）
- 入库：`POST /api/works/:id/messages` 幂等 upsert；下一章以全部已入库消息为 history
- 断言方式：soft-check 收集器全量执行后聚合判定（保证 5 章全部生成入库，不因首个失败中断）
- 完整原文与断言矩阵：`v3/client/test-results/quality-artifacts.json`（gitignore 内）

- **质量评估（0.5/5，不及格）**：模型从第 1 轮起就完全未进入 Seraphina 角色扮演——自认「AI 助手」、否认森林存在、用自身知识把「影牙」答成魔兽世界副本、第 5 轮要求用户补充背景。世界书条目（艾尔多利亚/影牙/空地）确实注入了上下文（审计可证），但**模型选择了自身知识而无视上下文**

- **这是本次测试最有价值的负面发现**：chat 模式无预设时的角色扮演保持力不足，需要在产品层兜底

## 四、跨场景缺陷汇总（按严重度）

| # | 缺陷 | 场景 | 严重度 | 建议 |
|---|---|---|---|---|
| 1 | **chat 模式无预设时角色扮演退化**为通用 AI 助手，世界书内容被无视 | T5 | 高 | chat 作品创建时若未绑预设，默认注入最小 roleplay 系统指令；或在 UI 提示「chat 模式建议绑定预设」 |
| 2 | **思考过程原文入库**：社区预设诱导的 `<thinking>` 块、指令诱导的 markdown 提纲均随正文入库显示 | T4、T3 | 高 | 入库前（postprocessMessage）增加思考块剥离兜底（`<think>`/`<thinking>` 配对剥离）；或绑预设时自动推荐配套正则 |
| 3 | **「小说家:」/「Seraphina:」name 前缀残留**：上游把 assistant 消息的 name 渲染成说话前缀，多场景出现 | T1、T2、T5 | 中 | server claude 通道转换时不向模型暴露 name 字段，或入库前剥离行首 name 前缀 |

## 六、结论与改进建议

1. **novel 管线达到可用水平**：T1-T3 证明「组装 → 生成 → 后处理 → 入库 → 历史续写」全链路稳定，世界书语义与酒馆对齐良好，字数/预算/幂等均符合设计。中文生成质量 4+/5（MiniMax-M3 中文网文文笔流畅，长文不崩）。
2. **最高优先级修复**（对应缺陷 #1、#2）：chat 无预设 roleplay 兜底 + 入库前思考块剥离。两者都是小改动（服务端/引擎层各一处），但对成品质感影响最大。
3. **中优先级**（缺陷 #3、#4）：name 前缀与标题解析的清洗增强，属 postprocess 管线的纯函数改动，可单测覆盖。
