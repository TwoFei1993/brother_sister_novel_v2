# 前端设计审计报告（v3 客户端）

- 审计日期：2026-10-20
- 审计对象：`v3/client`（React 19 + Vite 6 + Tailwind 4），dev 环境 `http://localhost:5173`（后端 3001）
- 审计方式：Playwright 截图驱动（44 张，桌面 1440×900 / 移动 390×844 / 7 套主题 / 商务白对比），辅以源码只读核对。全程未修改任何代码与用户数据（空态经网络层 mock，生成中状态未实际触发以避免写库）。
- 截图目录：`v3/client/test-results/design-audit/`
- 评分口径：每张截图按 7 条准则打分（1–5）：反 AI 味 / 排版层级 / 色彩系统 / 状态完备性 / 交互反馈 / 响应式触控 / 细节打磨。

## 一、总体印象与最突出的 3 个优点

整体是一个完成度中上的创作工具界面：信息架构清晰（书架 → 工作台三视图 → 资产库/设置），题材换肤体系是全站最有想法的部分，中文长文阅读的排版质感明显高于一般 AI 生成页面。主要短板集中在：emoji 图标体系、移动端底部指挥条布局、默认暗色主题的"紫 accent 模板脸"，以及 chat 气泡 markdown 未渲染这一处功能性硬伤。

**优点 1：中文正文排版质感好，沉浸阅读（B 视图）成立。**
衬线正文（玄幻主题 Noto Serif SC）+ 舒适行高段距 + 可调字号/行宽/日夜间四档阅读色（`d05-work-b.png`、`m03-work-b.png`）。段落节奏、标点渲染、中英文混排间距都在线，是全站最接近"出版级"的部分；TXT 导出直达也是正确的阅读器思维。

**优点 2：状态完备性的底子好。**
书架空态不是一块白板，而是"📚 书架空空如也 + 三步开始第一本书"引导卡并附三个分流按钮（`d02-bookshelf-empty.png`）；登录错误态有 `role=alert` 红字提示与 autoFocus（`d01b-login-error.png`）；工作台左栏每个模块都有空态文案（"还没有发送过指令"等，`d06-work-c.png`）；生成中有 animate-pulse 呼吸块（ReadingView/DialogView/MessageBubble）+ TypewriterPacer 打字机 + SSE 断流保护（代码核实）。

**优点 3：题材换肤体系架构完整，两套主题个性真正成立。**
7 套主题全部经 `[data-theme]` CSS 变量驱动并派生 v3 组件变量，作品按 genre 自动挂主题、用户固定主题可全局覆盖（`src/lib/theme.ts`），穿越主题的"宣纸米色 + Ma Shan Zheng 书法标题 + 金棕 accent"（`t-chuanyue-bookshelf.png`）与星际主题的"深空蓝黑 + 青色 + Orbitron"（`t-scifi-workb.png`）换肤后气质完全不同，说明变量体系是真通了的，不是摆设。

## 二、问题清单

### 【高】必修（影响可用性或构成功能性缺陷）

**H1. chat 气泡 markdown 完全未渲染，`**`、`-`、`---` 以字面文本显示**
- 截图：`d07-chat.png`、`m06-chat.png`（质检T5 角色 Seraphina 的回复）
- 位置：`src/features/chat/ChatBubbles.tsx`（源码注释自认："展示为纯文本（whitespace-pre-wrap）；markdown+DOMPurify 渲染由视图接线任务统一接入"—— TODO 一直未接线）
- 现状：LLM 回复几乎必带 markdown（列表/粗体/分隔线），用户看到的是满屏星号与横线，且有序列表编号、emoji、正文挤在一起。
- 建议：项目已有 `react-markdown` + `rehype-sanitize` + `src/lib/markdown.ts`，把 ChatBubbles 的 `{content}` 换成 `<MarkdownContent content={content} className="…"/>`（复用 novel 侧同一渲染管线，`ol/ul` 加 `ps-6 list-decimal/disc`，`hr` 用 `border-[hsl(var(--border-soft))]`）。工作量小、收益最大。

**H2. 移动端底部指挥条：剧情指令输入框被压缩到约 3 个字宽，基本不可用**
- 截图：`m03-work-b.png`、`m04-work-c.png`、`m05-work-drawer.png` 底部
- 位置：`src/features/workbench/CommandBar.tsx` —— 输入框 `min-w-0 flex-1` 与 `▶续写 / ⚡连写 / ? / 🎲换一支 / ?` 同行，移动端被 flex 挤扁；两个 `?` 帮助图标还常驻占宽。
- 建议：`md` 以下改为两行布局——第一行输入框独占整行（`w-full`），第二行按钮组右对齐；帮助图标收纳为单个 `?`（点击弹出说明）或仅在桌面显示。同时给输入框设 `min-w-32`，保证最差情况下仍可输入。

**H3. 移动端 TTS 速度条横向溢出，`1.2x/1.5x/1.8x/2x` 被裁切在屏外**
- 截图：`m03-work-b.png`、`m04-work-c.png`（右下 TTS 行）
- 位置：速度档位行（0.8x–2x）未做溢出处理，父容器 `overflow` 可见但视口裁切。
- 建议：该行加 `overflow-x-auto no-scrollbar`（横向滑动，两端渐隐 mask），或折叠为「1x ▾」下拉选择；`overscroll-behavior-x: contain` 防滑动冲突。

**H4. 多套暗色主题的次级文字对比度低于 WCAG AA（<4.5:1）**
- 截图：`d06-work-c.png`（左栏"世界书激活 0/0""还没有发送过指令"等灰字）、`d04-work-a.png`（开篇指令灰字）、`d16-settings-ui.png`（底部注释）
- 位置：`src/index.css` —— 实测对比度：玄幻 `[data-theme='xuanhuan'] --muted-foreground: 240 15% 50%` ≈ **3.6:1**；末世 `0 0% 50%` ≈ 4.4:1；无限流 `260 15% 50%` ≈ 4.3:1；穿越亮色 `25 15% 45%` ≈ 4.3:1。仅默认 :root（60%）与商务白（39% on white≈7:1）达标。
- 建议：把上述主题的 `--muted-foreground` 亮度统一提到 58%–62%（玄幻 `240 15% 60%`、末世 `0 0% 62%`、无限流 `260 15% 60%`、穿越 `25 12% 38%`），一行变量改动即可全站生效。

**H5. 移动端作品卡操作按钮是无文字的彩色 emoji，语义不可辨**
- 截图：`m02-bookshelf.png`（每张卡下方 `✍️ / ✏️ / ❌` 三个黑块按钮）
- 位置：`src/features/bookshelf/WorkCard.tsx`（`✍` 等 emoji 按钮）
- 现状：✍️（续写？编辑？）、✏️（改名？）、❌（删除）完全靠猜；删除是危险操作却以玩具感 emoji 呈现，与桌面端 library 的红边"删除"文字按钮风格割裂。
- 建议：改为单色 SVG 图标（lucide 的 `PenLine`/`BookOpen`/`Trash2`）+ `aria-label`；删除按钮统一用 `hsl(var(--danger))` 描边样式并弹确认；三个按钮不足 44px 高度的补足触控目标。

### 【中】应修（明显的品质与一致性损失）

**M1. 全站图标 = 彩色 emoji 与 CSS 混排，是"AI 味"最大来源**
- 截图：`d03-bookshelf.png`（顶栏 🗂 资产库 / 📑 大纲向导 / ⚙ 设置）、`d05-work-b.png`（视图 tab 💬📖🛠️ + 🎲换一支）、`d02-bookshelf-empty.png`（📚 空态）、`m06-chat.png`（↺ 🔊）
- 建议：引入 `lucide-react`（单色、随 `currentColor` 换肤），顶栏/按钮/空态图标全部替换；emoji 仅保留在用户内容里。这一条改完，精致度上一个台阶。

**M2. B tab 图标 📖 与"章节目录"按钮 📖 同屏重复，语义混淆**
- 截图：`d05-work-b.png` 顶栏（view-switcher 内 📖 选中块，右侧相邻又一个 📖）、`m03-work-b.png` 同样问题
- 位置：`src/pages/WorkPage.tsx` VIEW_TABS 与章节目录按钮（`aria-label="章节目录"`）
- 建议：章节目录改用 `List`/`Library` 图标，视图 tab 保留 📖 或换 `BookOpenText`。

**M3. 设置页主题选择器：色板预览小到无法传达主题差异**
- 截图：`d16-settings-ui.png`（7 个主题卡只有名字 + 一个约 28px 小圆点）
- 位置：`src/features/settings/ThemePanel.tsx`（Swatch = 大圆底色 + 右下 2.5 单位 accent 小点）
- 建议：把每张主题卡升级为迷你预览：`<div style={{background:hsl(bg)}}>` 内放一行 `font-heading` 样张标题 + 一个 accent 底色小按钮 + surface 色条，用户所选即所见。数据 `USER_THEME_OPTIONS.swatch` 已经有了，只差渲染。

**M4. 资产库每行 4 个按钮平铺，删除（危险）与普通操作等权常驻**
- 截图：`d08-library-characters.png`（6 行 × 编辑/导出PNG/导出JSON/删除）
- 位置：`src/features/library/AssetPanel.tsx`
- 建议：行内保留「编辑 + ▾ 更多」（导出/删除收进菜单）；删除项用 `--danger` 红字 + 二次确认弹层。视觉噪音立降，误触风险同步消除。

**M5. Toast 是文档流内联条，不是浮层——长页面操作反馈经常在视口外**
- 截图：`d08-library-characters.png`（toast 出现位置在页头下方；资产列表长时滚动到底部操作后不可见）
- 位置：`src/pages/LibraryPage.tsx`（`mb-4` 内联）、OutlineWizard 同模式
- 建议：抽一个 `<ToastHost>`，`fixed top-4 right-4`（移动端 `bottom-[calc(env(safe-area-inset-bottom)+16px)]` 居中），带淡入位移与 4s 自动消失；成功/错误色走 `--accent`/`--danger` 变量。

**M6. B 视图阅读工具条常驻，移动端占两行近 15% 屏高，与"沉浸"相悖**
- 截图：`d05-work-b.png`、`m03-work-b.png`（白天/夜间/护眼/深空 | 字号 | 行距 | TXT 全部平铺）
- 建议：工具条默认收起，正文区单击/上滑唤出后 3s 自动隐藏（阅读类 App 惯例）；至少移动端折叠为「Aa」一个按钮弹出面板。

**M7. 商务白主题下中文正文回落宋体，与 Inter 西文混排脱节**
- 截图：`b02-business-workc.png`（正文衬线宋体 + 西文 Inter）
- 位置：`src/index.css` `[data-theme='business'] --theme-font-body: 'Inter', sans-serif` —— Inter 无中文字形，中文落到浏览器默认（Windows 为宋体衬线），与 UI 其余部分的黑体割裂。
- 建议：改为 `'Inter', 'Noto Sans SC', 'Microsoft YaHei', sans-serif`；若想要"商务衬线"阅读感，显式声明 `'Noto Serif SC'` 而不是交给运气。

**M8. A（对话流）与 B（沉浸阅读）视图视觉差异过小，"对话流"语义没做出来**
- 截图：`d04-work-a.png` vs `d05-work-b.png` —— A 只是把 B 的正文装进一个圆角卡片，工具条还消失了（阅读设置在 A 中不可用，功能不一致）。
- 建议：A 视图做时间线感——章节间隔用居中装饰符（◆ 或章节名胶囊），指令/正文分色分形；或直接在 A 中保留阅读设置入口。二选一，消除"两个一样的视图"的困惑。

**M9. 书封渐变硬编码 Tailwind 色板，与主题 accent 不同源**
- 截图：`d03-bookshelf.png`（玄幻作品=紫→橙渐变，而玄幻主题 accent 是金色）、`b01-business-bookshelf.png`（商务白下深紫封面依旧）
- 位置：`src/features/bookshelf/genres.ts`（`from-indigo-800 to-amber-900` 等）
- 建议：把渐变视为独立"书封色板"集中注释管理可以接受，但至少：a) 修正与各题材主题 accent 的对应关系（玄幻金、科幻青、末世红…）；b) 商务白下给卡片加浅色变体或描边，避免白底上一排深紫块的突兀感。

**M10. 成功/警示色大面积硬编码 emerald/amber，白底主题下不达标**
- 截图：`b03-business-settings.png`（LLM 通道绿色"已配置"徽章）、代码核实 `SecretsPanel/MigratePanel/ResourceHub/OutlineWizard` 共 10+ 处 `text-emerald-400/500`、`bg-amber-400/15`
- 现状：emerald-400 (#34d399) on white ≈ 2.2:1，商务白下既刺眼又不达标；暗色主题下绿/金也不随主题。
- 建议：index.css 增补 `--ok`（成功）/`--warn`（进行中）两个语义变量并按主题派生（暗色 emerald-400、商务白 emerald-600），全站替换。

### 【低】可修（打磨项）

**L1. 登录页无品牌记忆点**（`d01-login.png`）：黑底 + 一张低对比卡片 + 系统字体标题，shadow-xl 在纯黑底上不可见。建议给卡片加 1px accent 描边或标题用书法/衬线字体 + 一枚简单 logo 图形；"进入书房"文案很好，视觉应配得上它。
**L2. 登录错误态输入框无红描边**（`d01b-login-error.png`）：仅文字变红，建议 `error && border-[hsl(var(--danger))]`。
**L3. 排序控件是原生 select**（`d03-bookshelf.png` 右上"最近更新"）：原生下拉箭头与整体风格不符，建议自定义外观（`appearance-none` + SVG 箭头）。
**L4. 章节标题层级弱**（`d05-work-b.png`）：标题仅约正文的 1.4 倍，建议 1.6–1.75 倍 + 上方 2 倍段距 + 主题色细节（如标题前金色短竖线）。
**L5. `{{char}}` 字面直接暴露在资产描述里**（`d08-library-characters.png`"{{char}}的身份是妹妹"）：展示层替换为资产名或高亮为徽章。
**L6. 大纲向导首屏空旷、无步骤感**（`d17-wizard.png`）：整页只有 textarea + 一个灰按钮。建议加 3 步指示器（粘贴 → 抽取 → 生成入库）+ 右侧说明栏；按钮 disabled 态与 hover 态区分度再拉开。
**L7. hub 的过滤 chips 与顶部 Tab 语义重叠**（`d12-library-hub.png`）：资源中心内又有"全部/预设/世界书/角色卡/正则"一层过滤，建议保留（它是搜索结果过滤）但在视觉上降级为次要样式，避免两层 tab 感。
**L8. 书架同日更新的作品无法区分先后**（`d03-bookshelf.png` 全部显示 2026/10/19）：副行显示相对时间（"3 小时前"）即可。
**L9. hub 的 AGPL-3.0 绿徽章硬编码**（`d12-library-hub.png`）：并入 M10 的 `--ok` 变量。
**L10. 阅读模式色走 JS 内联而非 CSS 变量**（`index.css` 中 `[data-reading]` 变量已定义但组件未消费）：建议 ReadingView 迁移到变量取色，减少双轨。
**L11. 视图切换无过渡动效**：A/B/C 切换与 swipe 候选切换（`data-testid="swipe-btn"`）均为内容瞬变，建议 150–200ms 淡入 + 轻微位移，配 `prefers-reduced-motion` 降级。
**L12. chat 成员栏过高且信息冗余**（`d07-chat.png` 顶部约 240px）："下一位：Seraphina" 胶囊 + 大头像 + 截断名 "Seraph…" 三者重复表达；建议压缩为一行（小头像 + 名字 + 下一位徽章），消息区多出 120px。

## 三、主题系统专项（7 套逐套评价）

| 主题 | 一句话评价 |
|---|---|
| 默认暗色（:root） | 黑底 + 紫罗兰 accent（262 60% 60%）恰好是"AI 生成页"的暗色模板脸，login/library/settings 未挂题材时全部露馅——**最该换掉 accent 的一套**。 |
| 穿越重生 chuanyue | 宣纸米底 + Ma Shan Zheng 书法标题 + 金棕 accent，7 套中辨识度最高、个性真正成立，唯一让人想截图分享的主题。 |
| 星际科幻 scifi | 深空蓝黑 + 青色 accent + Orbitron 标题，氛围到位；正文全黑体读长文略平，可给正文也配一点科幻感（字距微调或青色段标）。 |
| 末世求生 moshi | 纯灰黑 + 血红 accent，克制有效；但缺一层"废土质感"（噪点/扫痕纹理），且 muted 对比度全站最弱。 |
| 无限流 wuxian | 紫底紫 accent 与默认暗色难区分，Cinzel 只作用于拉丁字形、中文完全无感——个性基本没落地。 |
| 玄幻修仙 xuanhuan | 深蓝紫 + 金 accent + 衬线正文，书卷气成立、是最协调的暗色套；可惜 muted 3.6:1 不达标拖了后腿。 |
| 混合暗色 hunhe | 紫金搭配尚可，但"混合"定位模糊，观感接近"默认暗色换金 accent"，与无限流同患：Cinzel 对中文无效。 |
| 商务白 business | 蓝白克制、专业感最好，是唯一亮色底；硬伤是中文正文回落宋体（M7）与硬编码绿/金徽章不达标（M10）。 |

跨主题的两个结构性观察：
1. **默认 :root 与"无限流/混合"三套都偏紫**，是"6+1 主题"被感知为"其实只有 4 种颜色"的根源；建议默认主题 accent 换出紫色系（暖橙/青玉），或把无限流推向靛蓝+电光青。
2. **换肤变量覆盖了 90% 界面，但三处绕过了体系**：书封渐变（genres.ts）、成功/警示徽章（emerald/amber 硬编码）、彩色 emoji——它们是"切到商务白/穿越后仍然像暗色站"的全部原因。

---

## 四、与「AI 味」准则的差距总结

1. **配色**：没有踩"白底紫渐变"的字面坑，但默认主题"黑底紫 accent" + 书架大面积 `violet/indigo/purple` 书封渐变，构成了它的暗色变体。题材主题本身个性成立（尤其穿越/科幻/玄幻），一旦回到不绑题材的全局页（login/library/settings），立刻退回模板脸。差距主要在**默认主题的 accent 选择**，而非体系。
2. **字体**：题材主题内字体个性真实存在（书法/Orbitron/Cinzel/衬线），这是加分项；但全局页完全系统字体、无限流与混合主题的西文字体对中文无效，说明"字体个性"只做了半程。中文 webfont 加载依赖 Google Fonts，断网/国内环境回落系统字体后个性还会再打折。
3. **布局**：标准 Tailwind 卡片流 + 居中窄列，功能性合格但无记忆点；书架的竖版书封网格是唯一有"构图"意识的地方，值得在此基础上做更多（如书脊细节、阅读进度条压在卡片底部）。
4. **图标**：彩色 emoji 与单色 CSS 混排是当前与"精致成品"之间最直观的差距（M1/M2/H5），一处系统性替换即可消除大半"生成感"。
5. **结论**：这套 UI 的底子（变量体系、状态设计、中文排版）高于典型 AI 产出；"AI 味"集中在**默认主题观感、emoji 图标、硬编码色板**三个可枚举的点上，均可通过变量级/组件级小改动消除，不需要推翻重来。
